# Фото мест: загрузка из админки (локальный MinIO)

Фото мест лежат в S3-совместимом хранилище; в базе — только ключ файла (`place_photos.storage_key`),
публичный адрес = `MEDIA_BASE_URL/<ключ>`. Для разработки хранилище — бесплатный MinIO в Docker.
Продакшен-хранилище (бакет у хостера) настраивается теми же переменными, без изменений кода.

## 1. Запустить MinIO

```
make minio-up
```

Команда поднимает контейнер `minio` (S3 API — `127.0.0.1:9000`, веб-консоль — `http://127.0.0.1:9001`)
и разовый контейнер `minio-init`, который создаёт бакет `jol-media` и открывает его **на чтение** для
всех (фото публичные; писать можно только по ключам). Остановить: `make minio-down` (данные остаются в
томе `miniodata`). Базу и Valhalla эти команды не трогают.

Логин в консоль и ключи доступа по умолчанию — `jol_minio` / `jol_minio_dev_password` (только для
локальной разработки; поменять можно переменными `S3_ACCESS_KEY` / `S3_SECRET_KEY` в `.env` до первого
запуска).

## 2. Включить хранилище в `.env`

```
STORAGE_PROVIDER=s3
S3_ENDPOINT=http://127.0.0.1:9000
S3_BUCKET=jol-media
S3_REGION=us-east-1
S3_ACCESS_KEY=jol_minio
S3_SECRET_KEY=jol_minio_dev_password
MEDIA_BASE_URL=http://127.0.0.1:9000/jol-media
```

Перезапустить API (`make run`).

## 3. Загрузить фото в админке

1. `make admin-create EMAIL=you@example.com` (если админа ещё нет), открыть `http://localhost:8000/admin`.
2. «Места» → нужное место → блок «Фото» → «Выберите файл» → «Загрузить фото».
3. Файл должен быть JPEG, PNG или WebP до 8 МБ. Тип определяется по содержимому, а не по имени.
   Файл попадает в бакет под случайным именем `places/<id места>/<случайный id>.<jpg|png|webp>`
   и сразу появляется в списке фото места; в приложении он виден по адресу `MEDIA_BASE_URL/<ключ>`
   (в офлайн-копии поездки — поле `photo_url`).
4. Удалить фото можно кнопкой «Удалить» рядом с ним (из списка места; сам файл в бакете остаётся).

Если вместо загрузки видно «Хранилище фото не настроено» — не задан `STORAGE_PROVIDER` или `S3_*`.
Старый способ (вставить готовый ключ или `https://`-ссылку) остался в раскрывающемся блоке под кнопкой.

## Что проверено

- Загрузка в админке, проверка типа и размера, защита CSRF, ошибки хранилища — автотестами
  (`server/tests/test_admin_photos.py`).
- Адаптер S3 (`put` / `read` / `delete`) — вживую против S3-эмулятора `moto` (запись, чтение, удаление
  через HTTP работают). Эмулятор подписи не проверяет; корректность подписи SigV4 проверена тестом на
  примере из документации AWS (`test_storage.py`).
- **Не проверено вживую:** образы `minio/minio` и `minio/mc` и сама связка с MinIO — на машине, где
  писалась эта инструкция, Docker Hub не отдавал образы (ответ «pull access denied»). Compose-файл
  проходит `docker compose config`. При первом запуске у владельца: если тег образа не находится,
  возьмите свежий тег из релизов MinIO и поправьте его в `infra/docker-compose.yml`.
