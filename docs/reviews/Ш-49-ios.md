# Ревью Ш-49 (iOS) — кнопка и запрос бронирования

## Что сделано

- **Кнопка `place-book`** (`Features/Places/PlaceCardTabs.swift`) включена только если в JSON карточки `booking` не `null`, `available == true` и среди `kinds` есть вид, который знает приложение (`table`, `room`, `ticket`, `food`). Иначе остаётся выключенной с подписью «Бронирование здесь недоступно» (раньше — «скоро»). Решение принимает только сервер: клиент ничего не выдумывает.
- **Гость**: тап → окно входа (`AccountGate`), после входа открывается форма.
- **Форма** (`Features/Bookings/BookingSheet.swift`): вид (сегменты, если видов больше одного), дата и время (часовой пояс Алматы; для номера — даты заезда и выезда), число человек (1–20), необязательный комментарий. «Отправить запрос» → `POST /v1/bookings` (`place_id`, `kind`, `party_size`, `starts_at`/`ends_at` с смещением +05:00, `note`) с заголовком `Idempotency-Key`. Ключ держится, пока форма та же (повтор после обрыва не создаёт вторую бронь), при изменении полей — новый ключ. Для `food` дата не нужна.
- **Статус**: экран результата показывает статус сервера (`confirmed`, `pending`, `declined`, `cancelled`, иначе «не удалось связаться»), для `pending` — «Проверить статус» (`GET /v1/bookings/{id}`). Текст «Ничего не оплачено» — оплаты в приложении нет (SSOT §16.7 открыт).
- **Ошибки**: 422 `booking_not_supported`, 409 `booking_unavailable`, 422 неверная дата, 429, 401, нет сети — каждая со своей строкой.
- `Endpoint` получил поле `headers` (для `Idempotency-Key`).

## Проверки

- Юнит (`PlaceActionsTests`): разбор `booking` карточки (кафе — доступно, музей — `nil`, неизвестный вид или `available: false` — выключено), тело запроса и ключ, ключ при повторе и при изменении, отображение ошибок.
- UI (`PlaceActionsUITests`): музей без партнёра — кнопка выключена; кафе (партнёр) — кнопка включена, форма → «Подтверждено»; ответ 409 → строка ошибки; гость при действии на карточке видит окно входа.
- Скриншот результата в UI-тесте (вложение `booking-confirmed`); отдельный файл не снимался.

## Не сделано

- Нет списка моих броней (`GET /v1/bookings`) и отмены; заказ еды (`food`) — только форма запроса без меню.
- Билет на мероприятие (`event_id`) из карточки события не оформляется (только по времени).
- Форма не проверялась на реальном сервере (заглушка отвечает в тестах), Dynamic Type и тёмная тема не смотрелись.

## Пробелы серверного API

- В `booking` карточки нет данных, нужных форме: пределов числа человек, окна времени работы партнёра; клиент берёт 1–20.
- Прежнее ревью Ш-49 утверждало, что кнопка активна по партнёру — это стало правдой только теперь.
