# Ревью Ш-29 — слой LLM (fake-провайдер)

- Дата — 2026-11-21.
- Статус — готово для `fake`. Реальный провайдер не выбран (SSOT §16.12), адаптер не написан.

## Что сделано

`app/providers/llm/`:

- `base.py` — контракт. `LLMProvider.stream(messages, tools, system)` отдаёт типизированные
  события: `TextDelta`, `ToolCall` (id, имя, JSON-аргументы строкой), `Usage` (input/output),
  `Done`, `ErrorEvent`. `parse_tool_args(call, PydanticModel)` проверяет аргументы вызова
  инструмента и поднимает `ToolArgsError` (в сообщении только имена полей, не значения).
  Структурный вывод = инструмент со схемой результата (`ToolSpec.from_model`). `collect()`
  собирает поток в `Completion` и превращает `ErrorEvent` в `LLMError`.
- `resilient.py` — `ResilientLLM`: дедлайн одной попытки, повторы с экспоненциальным бэкоффом
  (0,5 с, 1 с, ... до 8 с) для ошибок с `retryable=True` и таймаутов, учёт токенов
  (`TokenCounter`). Повтор только пока клиенту ничего не отдано: уже показанный текст не вернуть,
  после первого события ошибка уходит как `ErrorEvent`. `stream` не бросает исключений
  провайдера, а завершается `ErrorEvent`.
- `fake.py` — `FakeLLM`: сценарий шагами (`Step`: куски текста, вызовы инструментов, задержка,
  ошибка до или после вывода, свой `Usage`) либо правилами «регулярное выражение по последнему
  сообщению пользователя»; пишет `calls` для проверок; токены по умолчанию — оценка 4 символа
  на токен.
- `__init__.py` — фабрика `get_llm_provider` по `LLM_PROVIDER` (`fake`, старое значение `stub`
  тоже работает): `fake` только в dev/test; любое другое значение даёт `LLMNotConfigured` с
  пометкой `OPEN(SSOT §16.12)`. `get_resilient_llm` берёт `LLM_TIMEOUT_SEC` (60) и
  `LLM_MAX_RETRIES` (2) из настроек. Значение по умолчанию `llm_provider` изменено с `stub` на
  `fake`, `.env.example` обновлён.

`app/chat/prompts/` — загрузчик и файлы `<имя>.<язык>.v<N>.md`: `trip_brief` (порядок
вопросов: даты, бюджет на всю поездку в тенге, жильё; остальное по ходу, без анкеты; инструменты
`update_trip_brief`, `add_graph_node`, `search_places`, `build_trip`) и `guest` (простой
ассистент без памяти, только `search_places`, предлагает войти ради персонального маршрута),
RU и EN. Загрузчик берёт последнюю версию, неизвестный язык заменяет на `en`, убирает
HTML-комментарии, `render()` подставляет `{{today}}`; `Prompt.id` вида `trip_brief.ru.v1` можно
писать рядом с ответом. В `pyproject.toml` добавлен `package-data` для `*.md`.

## Замечания

1. **Реального провайдера нет** (блокер до решения §16.12): форматы событий выбраны
   нейтральными; нужен адаптер, который переводит потоки конкретного API в эти события и
   классифицирует ошибки на повторяемые.
2. **Промпты — первый черновик** (средняя): не проверялись на реальной модели; инструменты
   описаны по плану Ш-31, но самих инструментов и их схем ещё нет. Переписать после Ш-31.
3. **Таймаут — на всю попытку**, а не на паузу между событиями (низкая): для длинных ответов
   реального провайдера может понадобиться «idle timeout».
4. **Учёт токенов только в памяти** (низкая): `TokenCounter` не пишется в БД; лимиты и учёт
   стоимости — в Ш-30/Ш-31.
5. Структурный вывод без инструментов (JSON-режим провайдера) не поддержан, только через
   tool call.
