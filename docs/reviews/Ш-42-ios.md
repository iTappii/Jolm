# Ревью Ш-42 (iOS) — скачанный маршрут (SSOT §7.4)

## Что сделано

- **Загрузка** (`Features/Offline/OfflineTripsModel.swift`, `TripService.offline`). `GET /v1/trips/{id}/offline` с токеном. Если копия уже есть, запрос идёт с `If-None-Match: <ETag копии>`; `304` значит «копия актуальна», тело не качается. `APIClient.sendConditional` — новый метод клиента: пропускает `304` как обычный ответ, возвращает `.notModified` или тело с заголовком `ETag`, для такого запроса отключает локальный кэш URLSession (иначе кэш мог бы ответить вместо сервера). Остальной `APIClient` не менялся.
- **Хранение** (`OfflineTripStore`). Один файл на поездку: `Application Support/Jol/OfflineTrips/<trip-id>.json` с `{meta: {etag, saved_at}, trip: <ответ сервера как есть>}`. Запись атомарная, защита файла `completeUntilFirstUserAuthentication`. Повреждённый файл считается «не скачано». Версия поездки лежит внутри `trip.version`.
- **Кнопка «Скачать маршрут»:** на полной карте — круглая кнопка справа в верхней панели (стрелка → индикатор → галочка; тап по галочке спрашивает «Удалить скачанный маршрут?»); в боковой панели «Мои поездки» — такая же иконка справа в каждой строке. Только для вошедшего. Ошибка загрузки показывается строкой («Не удалось скачать маршрут. Проверьте соединение.» или текст сервера).
- **Без сети.** `TripMapModel.open` при `APIError.network` берёт сохранённую копию: `OfflineTrip.overview()` собирает из неё тот же `TripOverview`, что рисует обычная карта, так что дни, нумерованные остановки с `HH:mm–HH:mm`, стоимость и линии переходов (polyline6 выбранного вида) рисуются прежним кодом. Копия только для чтения: кнопки «убрать», лист вида транспорта, бюджет отключены, `chooseMode/choose/remove/selectLeg` в модели ничего не делают при `isSavedCopy`. В панели строка «Нет сети. Это копия, сохранённая на устройстве…» (карта без тайлов может быть пустой). Карточка места из копии — свой лист `TripOfflinePlaceSheet`: название, категория, время и цена посещения, часы работы дня посещения (день недели считается по дате, 0 = понедельник), адрес. Без фото, отзывов и брони (в копии их нет).
- **«Мои поездки» без сети:** `loadSummaries` при `APIError.network` показывает скачанные поездки (даты, число дней), а не ошибку.
- **Копия следует за планом.** После успешной онлайн-загрузки поездки и после каждой правки (`refresh`) вызывается условный запрос: `304` ничего не стоит, новая версия заменяет файл.
- **Выход / удаление аккаунта.** Копии стираются (`HomeScreen`, ветка «не вошёл»): сохранённый план — личные данные аккаунта.
- Заглушка для UI-тестов (`UITestExtraStub.swift`): `/offline` с `ETag` и `304`, флаг `-JolStubOffline` (все запросы падают как `notConnectedToInternet`), `-JolResetOffline` (чистит скачанное перед тестом).

## Проверки

- Юнит `OfflineTripTests` (13): файл хранит копию, версию и `ETag` между экземплярами, без остатков временных файлов; удаление и повреждённый файл; первая загрузка без `If-None-Match`, вторая с ним и `304` оставляет копию; новая версия заменяет файл и `ETag`; сбой сети ничего не сохраняет и не трогает старую копию; ошибка сервера и стирание при выходе; копия → план со временем и линией перехода; остановка без места пропускается; часы работы по дню недели; карта открывает копию без сети (read-only, правки не шлют запросов); без копии карта падает, как раньше; онлайн-загрузка побеждает копию и обновляет её; «Мои поездки» из скачанных.
- UI `OfflineTripUITests` (1): первый запуск скачивает поездку из «Мои поездки» (подпись кнопки меняется на «Route downloaded»), второй запуск с `-JolStubOffline` (любой запрос падает): поездка есть в списке, карта открывается, обе остановки дня 1 с `09:30–11:00` и `12:00–13:30`, переход, день 2 с `10:00–11:30`, кнопок «убрать» нет, карточка места показывает название, адрес, часы и время визита.

## Не сделано / ограничения

- Офлайн-тайлы карты (SSOT §16.6) не качаются: без сети карта показывает только то, что MapLibre успел закэшировать, поэтому в панели есть примечание. Список и линии переходов в панели/на карте работают в любом случае.
- Мероприятия, фото, бронирование, бюджетные варианты в копию не входят (сервер их не отдаёт); в режиме копии чип бюджета отключён.
- Жильё в копии нет (в плане его нет остановкой, см. ревью сервера).
- Язык копии — язык на момент скачивания; при смене языка копия обновится при ближайшей онлайн-загрузке этой поездки (`ETag` зависит от языка).
- Размер файла на длинной поездке не измерялся; чтение синхронное на главном потоке (файлы небольшие).
- На устройстве и в настоящем авиарежиме не проверялось (симулятор, сбой имитирован заглушкой).
- Автоскачивание нового маршрута после его построения не делается: только по кнопке (в SSOT оно не требуется).

## Пробелы серверного API

- В ответе `/offline` нет `photo_url` (пока `MEDIA_BASE_URL` пуст), нет мероприятий дат поездки и бюджетной разбивки; без них скачанная копия беднее онлайн-плана.
- ETag не меняется при правке данных места (часы, адрес) без новой версии поездки — копия такие правки не подхватит (уже отмечено в ревью сервера).

## Перепроверка (2026-11-21, независимо от автора)

Что проверено по коду, а не по ревью:

- **Контракт сервера.** `GET /v1/trips/{trip_id}/offline` есть в `server/app/trips/api.py` (строка ~117), ответ собирает `read.offline_json`: ключи верхнего уровня (`trip_id, version, locale, timezone, start_date, end_date, budget_kzt, total_cost_kzt, days, places`), дней (`date, items, legs`), остановок (`id, ord, kind, meal, place_id, starts_at, ends_at, visit_min, must_have, est_cost_kzt`), переходов (`id, from_item_id, to_item_id, depart_at, travel_s, estimated, mode, cost_kzt, distance_m, geometry`) и мест (`name, name_lang, names, category, category_name, lat, lon, address, hours, photo_url`) совпадают с `OfflineTrip`/`OfflineDay`/`OfflineItem`/`OfflineLeg`/`OfflinePlace` один в один, включая `CodingKeys`.
- **ETag.** Сервер отдаёт `"v<версия>-<язык>"` и `304` по `If-None-Match`; язык берётся из `Accept-Language`, который `APIClient` шлёт всегда, поэтому смена языка приложения даёт другой ETag и свежую копию. `sendConditional` ставит заголовок и обходит локальный кэш URLSession.
- **DoD «в авиарежиме открывается скачанный маршрут со всеми временами».** Ветка `TripMapModel.open` → `openSavedCopy` срабатывает только на `APIError.network` (любой `URLError`, кроме отмены, нормализуется в `.network`), собирает `TripOverview` из копии с `HH:mm–HH:mm`, линиями переходов и без правок (правки отключены в режиме копии). Выход из аккаунта стирает копии (`HomeScreen`).
- Нашёл ли ошибки: **нет**. Расхождений с DoD и серверным API нет.
