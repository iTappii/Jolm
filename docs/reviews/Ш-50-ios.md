# Ревью Ш-50 (iOS) — отправка событий

## Что сделано

- **`AnalyticsClient`** (`Features/Analytics/`): три клиентских события из белого списка сервера (`server/app/analytics/events.py`):
  - `app_install` — один раз за установку (флаг `jol.analytics_installed` в `UserDefaults`, сбрасывается с переустановкой), перед первым `app_launch`;
  - `app_launch` — при каждом запуске (`RootView`, `.task`); свойства `app_version` и `locale` (`ru`/`en`) — обе в белом списке сервера;
  - `directions_start` — кнопка «Открыть в навигаторе» (Apple Карты / 2ГИС): `place_id` места-цели и `props.mode` (`walk|scooter|bus|metro|taxi|car`) — режим выбранного сейчас варианта в карусели «Как добраться». С карточки места (без маршрута) кнопка шлёт событие без `mode`.
  Координат и свободного текста в событиях нет: только имя, время, `place_id` и `mode`/`app_version`/`locale`.
- **Очередь на диске** (`AnalyticsQueueStore`): `Application Support/Jol/analytics-queue.json`; повреждённый файл — пустая очередь; не больше 500 событий (старейшие вытесняются). `id` (UUID) создаётся при самом событии и не меняется, поэтому повтор пачки после потерянного ответа сервер считает дубликатом.
- **Отправка пачками.** `POST /v1/analytics/events`, заголовок `X-Install-ID` (его ставит `APIClient`), `Authorization: Bearer` — когда человек вошёл (просроченный токен сервер игнорирует). Тело `{"sent_at": ISO-8601 с зоной, "events": [{"id","name","ts", "place_id"?, "props"?}]}`, 1–50 событий в пачке (длиннее очередь уходит несколькими). Когда: сразу при запуске, затем при каждой смене состояния приложения (в фон и обратно), через 10 с после нового события, сразу при накоплении 50.
- **Старше 7 дней** (по часам устройства) выбрасываются перед отправкой — сервер всё равно отказал бы.
- **Сбои.** `429` — события остаются, пауза = `Retry-After` сервера (не меньше текущей задержки); нет сети / `5xx` / `408` / `401` — события остаются, пауза 1, 2, 4 … минут, максимум час (сбрасывается после успеха); другой `4xx` (`400`, `413`, `422`) — пачка отвергнута целиком, её выбрасываем, чтобы не повторять вечно. Ответ `200` с `rejected` > 0 тоже снимает события из очереди (отклонённое повторять бессмысленно).
- Заглушка (`UITestExtraStub`) принимает `/v1/analytics/events` и пишет каждый вызов в системный лог строкой `JolStub …` (так связка проверена руками).

## Проверки

- Юнит `AnalyticsTests` (12): первый запуск = `app_install` + `app_launch`, дальше только `app_launch`, очередь переживает перезапуск; `directions_start` с местом и режимом и без них, в событии нет лишних ключей; форма тела, `X-Install-ID`, bearer (вошёл) / без него (гость), `sent_at` и `ts` ISO-8601 с зоной; 120 событий → пачки 50 + 50 + 20; повтор после сбоя сети идёт с теми же `id`; `429` с `Retry-After: 600` — пауза ровно 600 с, раньше срока запроса нет, после срока уходит и пауза снимается; задержка без `Retry-After` растёт 60 → 120 → … и упирается в 3600; `422` выбрасывает пачку без повтора; события старше 7 дней не уходят (и очередь из одних старых пуста, запроса нет); потолок очереди.
- UI `AnalyticsUITests` (1, заглушка): «Открыть в навигаторе» из «Как добраться» не ломает приложение. Содержимое запросов проверено руками по логу симулятора: при запуске ушёл `app_launch` (`app_version: 0.1.0`, `locale: en`), после нажатия — `directions_start` с `place_id` фикстурного места и `mode: walk`, `sent_at` и `ts` в UTC.

## Решения и замечания

1. **Что считать `directions_start`.** В плане написано «как добраться запущено»; режим (`mode`) известен только на выбранном варианте, поэтому событие шлётся при нажатии «Открыть в навигаторе», а не при открытии карусели. Если нужна метрика «открыли карусель», это отдельное событие и отдельное имя в белом списке сервера.
2. Событие `app_install` не шлётся повторно после переустановки только если `UserDefaults` пережил её (не переживает) — считается как новая установка, это ожидаемо.
3. Отправка в фоне не продлевается (`beginBackgroundTask` нет): если система приостановит приложение раньше ответа, пачка уйдёт при следующем запуске с теми же `id`.

## Перепроверка (2026-11-21, независимо от автора)

- **Контракт.** `POST /v1/analytics/events` есть в `server/app/analytics/api.py`: `X-Install-ID` обязателен (UUID), bearer необязателен и при протухании игнорируется; тело `{sent_at, events[1..50]: {id: uuid, name, ts, place_id?, props}}`, `extra="forbid"` на событии — `AnalyticsBatch.encode` пишет только `id, name, ts, place_id, props`, даты с зоной (`Z`). Клиентские имена `app_install, app_launch, directions_start` и свойства (`app_version, locale`; `mode` из `walk|scooter|bus|metro|taxi|car`) совпадают с `CLIENT_EVENTS`/`PROPS` в `events.py`. Лимит 429 с `Retry-After` обрабатывается, прочие 4xx выбрасывают пачку, 5xx/сеть — откат.
- **Очередь.** Идентификатор события создаётся один раз, повтор пачки сервер сведёт в `duplicates`; события старше 7 дней сервер отверг бы — клиент их выбрасывает сам.
- **Незафиксированная правка в рабочем дереве** (`NavigatorButton.mode` стал замыканием, `DirectionsPanel` передаёт `{ selectedMode }`): она корректна — режим читается в момент нажатия, панель не подписывается на состояние карусели ради одной кнопки; собирается, тесты зелёные. Закоммичена отдельным коммитом.
- Нашёл ли ошибки: **нет**. Замечание к Ш-23c (исправлено там): для нажатия «Открыть в навигаторе» на адресной точке `place_id` в событие не кладётся — у адреса его нет.
