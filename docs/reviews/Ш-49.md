# Ш-49. Каркас бронирований (SSOT §9)

Абстракция бронирований через адаптеры партнеров, таблицы связки мест с партнерами и бронированиями, заглушка `StubAdapter`, открытый API и UI-кнопка бронирования. Веха M5.

## Реализация

- **База данных:** миграция `db/migrations/0023_bookings.sql`: таблицы `partners`, `partner_places` (с массивом поддерживаемых типов: `table`, `room`, `ticket`), `bookings` (статусы: `pending`, `confirmed`, `cancelled`, `rejected`).
- **Правило 8 плана:** слияние мест в `data/osm/merge.py` переносит `partner_places.place_id` и `bookings.place_id` на сохранившееся место. Удаление аккаунта каскадно обрабатывает его бронирования.
- **Интерфейс адаптера (`PartnerAdapter`):** методы `check_availability`, `create_booking`, `get_status`. Реализован `StubAdapter` с детерминированным подтверждением тестовых дат.
- **API:**
  - `POST /v1/bookings` — создание запроса на бронирование (столик, номер, билет) с проверкой партнерства места.
  - `GET /v1/bookings/{id}` — статус бронирования для владельца.
  - `GET /v1/me/bookings` — список бронирований авторизованного пользователя.
- **Клиент и карточка места:** кнопка «Забронировать» (`place-book`) в карточке места активна только при наличии активного партнера у места.

## Проверка

- `server/tests/test_bookings.py` (9 тестов): проверка наличия мест, валидация полей, бронирование столика/номера/билета, права доступа, статусы, защита от дублей.
- Тест слияния дублей OSM в `test_osm_pipeline.py`.
- UI-тест в `PlacesUITests` подтверждает наличие элемента `place-book` на карточке партнерского места.
- Все тесты зелёные в составе `make ci`.
