# Ревью Ш-55 (сервер) — доработки без внешних сервисов

iOS-часть (Ш-37, Ш-49, Ш-52) делают другие агенты; здесь серверные пункты шага.

## Что сделано

1. **Ш-37: `GET /v1/trips/{trip_id}/items/{item_id}/alternatives`** → `{"items": [{id, name, category,
   lat, lon, price_kzt|null, distance_m}]}`. До 5 мест той же категории, что у остановки, активных и не
   жильё, ближайших к ней (при близких расстояниях раньше — более популярное: `_candidates` из `trips/edit.py`,
   как и у замены); мест, которые уже стоят в поездке, нет; для остановки-еды подходят только настоящие
   «места поесть». `price_kzt` — средний чек для заведений, цена входа для остальных, `null`, если неизвестна.
   `distance_m` — по прямой от остановки. Названия — по `Accept-Language`. 401 без токена; 404 для чужой/
   неизвестной поездки и неизвестной остановки. Замена — существующий `POST .../replace` с `place_id`
   (он по-прежнему может ответить 409 `no_replacement`, если место не влезает в день).
2. **Ш-49: `POST /v1/bookings/{id}/cancel`** → объект брони (как `GET /v1/bookings/{id}`) со статусом
   `cancelled`, `Cache-Control: no-store`. 404 — чужая/неизвестная; 409 `not_cancellable` — бронь уже не
   `pending`/`confirmed` (отменена, отклонена, не удалась) или её время начала прошло (проверка по
   `payload.starts_at` и `clock.now()`); 503 `booking_partner_unavailable` — партнёр не ответил, ничего не
   меняется. Партнёр спрашивается первым: у адаптера появился необязательный метод `cancel(external_ref)`
   (в `StubAdapter` реализован); ответ партнёра, отличный от `cancelled`, даёт 409, а бронь остаётся прежней.
   Строка брони блокируется `FOR UPDATE`, поэтому две одновременные отмены не вызывают партнёра дважды.
   Текст `not_cancellable` добавлен в i18n (ru/en). Лимита на отмены нет (она возможна только для живой брони).
3. **Ш-42: ETag офлайн-копии** теперь `"v<версия>-<язык>-<12 знаков sha1 тела>"`: тело (`offline_json`)
   собирается и хэшируется до сравнения с `If-None-Match`, поэтому любая правка данных мест поездки (имя,
   адрес, координаты, часы работы, фото) меняет тег, даже если версия поездки не выросла. Колонки
   `places.updated_at` в базе нет (есть только `data_updated_at`, которое не обновляется при правке часов и
   фото), поэтому вместо «максимума даты обновления» выбран хэш содержимого — он не зависит от того, кто и
   какой путь записи использовал. 304 по-прежнему не считается скачиванием в аналитике. Цена: тело строится
   на каждый запрос, как и раньше при 200; экономия трафика сохранена, экономии запросов к БД нет.
4. **Фото мест от владельца.** Проверка показала, что форма «Фото» в админке **не загружала файлы**: в ней
   было только поле «ключ в хранилище / https-ссылка» (заглушка с `TODO(Ш-44)`), а у `StorageProvider` не
   было серверной записи. Сделано: `put(key, content_type, data)` у `S3Storage` (подписанный PUT через
   httpx) и `LocalStorage`; в админке — поле выбора файла (`multipart/form-data`), проверка размера (≤ 8 МБ),
   типа по содержимому (JPEG/PNG/WebP, имя и заявленный тип не доверяются), ключ
   `places/<id места>/<случайный id>.<расширение>`, запись в хранилище и строка в `place_photos`; ошибки —
   понятным текстом (пустой файл, не тот тип, слишком большой, хранилище не настроено, сбой хранилища).
   Старый ввод ключа/ссылки сохранён в раскрывающемся блоке. В `infra/docker-compose.yml` добавлены
   `minio` и `minio-init` (профиль `minio`, только локально, порты на 127.0.0.1), цели `make minio-up` /
   `make minio-down`, переменные в `.env.example`, инструкция `docs/photos.md`.
5. **Не в этом отчёте:** Ш-52 (доступность, тёмная тема боковой панели и др.) — iOS.

## Замечания

- **Высоко (не проверено):** реальный MinIO не запускался — образы `minio/minio` и `minio/mc` не удалось
  скачать (Docker Hub отвечал «pull access denied»). Теги в compose взяты по памяти из списка релизов MinIO и
  не проверены; healthcheck `mc ready local` и `mc anonymous set download` тоже не прогонялись. Владельцу нужно
  один раз пройти `docs/photos.md`; если тег не находится — взять свежий.
- Средне: подпись SigV4 для PUT проверена только тестом на примере AWS и эмулятором без проверки подписи;
  настоящий MinIO её проверяет — это и есть остающийся риск (в первую очередь заголовок `content-length`,
  который подписывается).
- Средне: удаление фото в админке убирает строку, но не файл из бакета (как и раньше для ключей).
- Низко: ETag считает хэш по телу, которое включает `photo_url` от `MEDIA_BASE_URL`; смена базы URL тоже
  делает копию устаревшей — это нужное поведение.
- Низко: `alternatives` берёт пул из 40 мест категории (`CANDIDATE_POOL`); для очень частых категорий дальние
  места не попадут в выдачу, ближайшие — попадут.
