## Что сделано

- Миграция `db/migrations/0015_user_favorites.sql`: `user_favorites (user_id -> users ON DELETE
  CASCADE, place_id -> places БЕЗ каскада, created_at, PK (user_id, place_id))` и индексы.
  Применена `make migrate` (аддитивно, данные dev не тронуты).
- `data/osm/merge.py` (правило 8): при слиянии дублей места избранное переносится на
  выжившее; если у пользователя были оба, лишнее удаляется. Тест
  `test_merge_moves_user_favorites_to_the_survivor` в `tests/test_osm_pipeline.py`.
- `server/app/favorites/api.py`, роутер подключён в `main.py`. Только bearer-токен, гостю 401.
  - `GET /v1/me/favorites` -> `{"items":[...]}`, новые сверху, `Cache-Control: no-store`.
  - `PUT /v1/me/favorites/{place_id}` -> 204, идемпотентно; 404 для неизвестного или
    неактивного места; 409 `favorites_limit` при попытке добавить новое сверх лимита.
  - `DELETE /v1/me/favorites/{place_id}` -> 204, идемпотентно (в том числе для места,
    которого нет).
- Лимит: 500 на пользователя (`MAX_FAVORITES`), проверка под блокировкой строки пользователя.
  Значение — допущение, записано в `docs/adr/0003-open-defaults.md`.
- Удаление аккаунта: каскад через `users`; `tests/test_account_deletion.py` проверяет, что
  избранное удалённого пользователя исчезает, чужое остаётся. `user_favorites` добавлена в
  `AUTH_TABLES` в `tests/conftest.py`.
