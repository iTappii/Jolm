# Ревью Ш-36 — сборка в поездку (`build_trip`)

Цепочка: кандидаты (Ш-33) -> раскладка (Ш-34) -> жильё и бюджет (Ш-35) -> транзакционная
запись -> SSE `route_ready` -> компактный результат инструмента модели. Заглушка
`trip_build {"status":"not_implemented"}` удалена.

## Что сделано

- **Миграция `db/migrations/0011_trips.sql`:** `trips`, `trip_items`, `trip_legs`,
  `trip_lodging_options`. Деньги — `bigint` тенге, время — `timestamptz`. `trips.user_id` ->
  `users ON DELETE CASCADE`; все дочерние таблицы каскадом от `trips`. `place_id` в
  `trip_items` и `trip_lodging_options` — **без каскада** (правило 8).
  - Одна поездка на чат: `trips.chat_id UNIQUE` (`ON DELETE SET NULL`). Повторный `build_trip`
    обновляет ту же строку, `version` + 1, строки плана заменяются.
  - `trips.brief` — снимок брифа (в чате он может измениться); `brief_id` из черновика плана не
    нужен (бриф и так один на чат).
  - `trip_items.variant` (`main` / `drop_places` / `cheaper`): варианты при превышении бюджета
    лежат рядом с планом до выбора пользователя. **Читатели обязаны фильтровать
    `variant = 'main'`** (Ш-37).
  - `trip_legs.options` — все варианты транспорта Ш-22 без `steps` (маневры можно взять из
    `POST /v1/directions`), `chosen_mode` — вариант по умолчанию, `cost_kzt` — его верхняя оценка.
  - `event_id` не добавлен (мероприятия — Ф16).
- **`merge_place` (`data/osm/merge.py`):** `trip_items` переносятся на выжившее место,
  `trip_lodging_options` — тоже (при коллизии в одной поездке остаётся строка выжившего и
  переходит признак `recommended`). Тест `test_merge_moves_trip_rows_to_the_survivor`.
- **Удаление аккаунта:** тест `test_delete_removes_trips_with_items_legs_and_lodging_but_not_places`
  (чужие поездки и сами места остаются). `AUTH_TABLES` в `conftest.py` дополнен.
- **`build_trip`:** `app/planner/build.py` (сборка в памяти), `app/trips/store.py` (SQL),
  `app/chat/build_tool.py` (инструмент). Чтение — одна короткая транзакция, маршрутизатор
  вызывается без соединения. Valhalla недоступна — план строится по оценкам по прямой
  (`travel_estimated`). Роутер берётся из `app.state.routing_provider`.
- **Замечания координатора по Ш-34:** (1) обязательное место, не влезшее в свой день
  (`no_time`), повторяется на других днях — раскладка пересобирается до 3 раз с исключением дня
  для этого места, берётся проход с меньшим числом нераспределённых обязательных; (2) тест на
  детерминизм (3 запуска одного входа — одинаковый план, включая варианты бюджета).
- **Промпт `trip_brief.{en,ru}.v3`:** что говорить после `build_trip` (по дням, честно о
  превышении бюджета и невыполненных пожеланиях).

## SSE `route_ready` (точная форма)

```json
{"trip_id": "<uuid>", "version": 1, "days": 3,
 "warnings": [{"code": "over_budget", "date": null, "detail": "9000"}],
 "must_have_unmet": [{"wish": "суши-бар", "place_name": null, "reason": "no_place"}],
 "budget": {
   "budget_kzt": 900000, "status": "ok", "total_kzt": 120000, "remaining_kzt": 780000,
   "shortfall_kzt": 0,
   "breakdown": {"lodging_kzt": 0, "entries_kzt": 44000, "meals_kzt": 19500,
                 "transport_kzt": 4000, "events_kzt": 0},
   "assumptions": {"meals_assumed": 0, "entries_unknown": 3, "lodging_price_assumed": false},
   "must_have_cost_kzt": 4000, "must_haves_exceed_budget": false,
   "lodging": {"needed": true, "nights": 2, "cost_kzt": 12000, "price_assumed": false,
               "options": [{"place_id", "name", "category", "lat", "lon",
                            "price_per_night_kzt", "price_assumed", "total_kzt",
                            "distance_km", "recommended"}]},
   "variants": null,
   "choice": null}}
```

- `warnings[].code`: `travel_estimated`, `meal_missing` (date, detail = lunch|dinner),
  `hours_assumed` (detail = число мест), `over_budget` (detail = нехватка), `must_haves_exceed_budget`
  (detail = минимум для обязательных), `meal_prices_assumed` (detail = число), `lodging_price_assumed`,
  `no_lodging_found`.
- `must_have_unmet[].reason`: `no_place` (в базе ничего нет; `wish`), `closed_on_trip_days`,
  `no_time` (`place_name`). План строится в любом случае (SSOT §16.11).
- `budget.status`: `ok` | `over`. При `over` `variants` =
  `{"drop_places": {feasible, total_kzt, saves_kzt, shortfall_kzt, breakdown, removed_count,
  removed: [{place_id, name}]}, "cheaper": {feasible, total_kzt, saves_kzt, shortfall_kzt,
  breakdown, swaps_count, swaps: [{from: {place_id, name}, to: {place_id, name}}],
  lodging_changed, lodging_total_kzt, lodging: {place_id, name, total_kzt} | null}}`.
  Выбор — `POST /v1/trips/{id}/budget-choice`.
- В `trips.budget` (БД) лежит тот же блок **без идентификаторов мест** (`lodging.options`,
  `removed`, `swaps`, `lodging` опущены; остаются числа и счётчики), чтобы не протухали при
  слиянии мест. Состав вариантов — по строкам `trip_items` с `variant != 'main'`.
- `days` — число дней поездки; сам план клиент читает через `GET /v1/trips/{id}` (Ш-37, не
  сделан).

Результат инструмента для модели: `{ok, trip_id, version, days: [{date, stops: [{time, name,
kind, cost_kzt, meal?, must_have?}]}], budget (кратко), warnings: [codes], must_have_unmet,
instructions}`.

## Проверки

- `tests/test_trips.py`, 14 тестов: диалог (fake LLM) -> `build_trip` -> строки `trips`,
  `trip_items`, `trip_legs` (порядок, нет пересечений, обед и ужин каждый день, переходы между
  соседними остановками, сумма сходится с `budget.total_kzt`), `route_ready`, результат модели;
  повторная сборка (тот же `trip_id`, `version` 2 и 3, старые строки заменены, одинаковый план без
  изменений); пожелание без места; жильё и варианты; все сценарии бюджета (см. Ш-35); неполный
  бриф; Valhalla недоступна.
- `tests/test_planner_layout.py` +3: повтор обязательного на другом дне (с `MUST_HAVE_RETRIES = 0`
  воспроизводится потеря), честный `no_time` когда места нет, детерминизм.
- `make migrate` применён к dev-БД, `make ci`: 504 прошли, 1 пропущен (линтеры чистые).
- Прогон на реальной базе Алматы и реальном Valhalla (скрипт вне репозитория): 4 дня, 2 обязательных
  пожелания (кухня и Медеу), ~2 с, ни одного `unmet`.

## Не сделано / не проверено

- **`GET /v1/trips`, `GET /v1/trips/{id}`** — Ш-37, не добавлены (читатель должен фильтровать
  `variant = 'main'`, `trip_lodging_options` отдаёт варианты жилья).
- Прогноз погоды — `UnknownForecast` (Ф11); память и загруженность — пока пусты (Ф12, Ф15).
- Нет Valhalla в тестах (кроме Ш-34): сквозные тесты идут на `FakeRouter`.
- Запись и сборка вызываются в двух транзакциях (чтение / запись): между ними бриф не блокируется,
  но ход чата один (аренда хода), так что параллельной правки брифа нет.
- Правки (Ш-38), погодные предложения (Ф11), память (Ф12) к схеме не подключены.
- Нет ограничений на размер `options` у переходов; ~30 переходов × 4–6 вариантов с геометрией — сотни
  КБ на поездку при большом числе дней (при необходимости хранить геометрию только выбранного).
