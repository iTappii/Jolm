# Ревью Ш-33 — отбор кандидатов

Модуль `server/app/planner/` (без модели, детерминированный). `select_candidates(conn, brief,
memory, crowd, event_bonus)` берёт бриф с датами и возвращает `Selection`: места под
обязательные пожелания, пул «активностей» и пул «еды» с оценками. В `build_trip` не подключено
(это Ш-36); раскладка по дням (Ш-34) не делалась.

## Что сделано

- **Обязательные пожелания** (`candidates._resolve_must_have`). Текст читается по таблице
  ключевых слов RU+EN (`interests.py`: «восточная кухня», «китайская еда», «плов», «музеи»,
  «горы» → категории). Сначала поиск по названию (`pg_trgm`, `word_similarity`, как в
  `places`) — одно место; затем категория — до `places_per_must_have(дни)` мест (1 на 1–2 дня,
  2 на 3–5, 3 от 6), самые популярные. Слова, являющиеся категорией, совпадают с названиями
  только строго (≥0.8), чтобы «park» не давал каждый «Park Hotel»; неизвестное слово ищется по
  названию с подстрокой и сходством ≥0.4. Место, уже отданное прошлому пожеланию, повторно
  берётся только если больше нечего (каждое пожелание получает место). Ничего не нашлось →
  пожелание остаётся в `must_haves` без мест и в `Selection.must_have_unmet`
  (`# OPEN(SSOT §16.11)`); молча не отбрасывается. Места пожеланий не попадают в пулы второй раз.
- **Скоринг** (`scoring.py`, чистые функции):
  `score = 3.0·интерес + 2.0·популярность − 2.0·память − 1.5·толпа·нетерпимость + 1.0·событие·k`.
  Интерес: 1.0 категория совпала, 0.5 совпала группа (например `food`), +0.5 для outdoor-места
  при интересе «на природе»; итог ≤1. Популярность = `popularity/100` (в сидах 0..100).
  Память: `max(memory[категория], memory[группа])`, 0..1 (интерфейс — отображение; Ф12 пусто).
  Толпа: `CrowdSource.level(place_id)` 0..1 или `None`; нетерпимость = `(4 − crowd_tolerance)/4`
  (нет значения → 2, т. е. 0.5); `UnknownCrowd` всегда `None` — штрафа нет. Событие: хук
  `event_bonus(place, start, end)`, по умолчанию 0 (события не загружены); `k` = 1, если
  турист просил события, иначе 0.5. Ничьи — по популярности, затем по `id`.
- **Размер пула**: активностей в день 3/4/6 (calm/normal/dense; нет темпа → normal) × 1.5 (запас
  для раскладки), еда — 2 приёма × 1.5 в день; потолки 250 и 150. Примеры: 3 дня normal → 18 + 9;
  7 дней dense → 63 + 21; 1 день calm → 5 + 3. Места пожеланий вычитаются из своего пула, но
  никогда не обрезаются. Одна категория занимает не более 40% пула, пока есть другие
  (в запасе — добираем из «переполненных»).
- Только `status='active'`, bbox Алматы (`area.ALMATY_BBOX`), без жилья (Ш-35). Часы работы
  не фильтруются — это Ш-34.

Миграций нет, таблиц с `place_id` нет — правило 8 не затронуто.

## Замечания и отложенное

1. **Средняя.** Ключевые слова — ручная таблица. Неизвестное слово («каток») без совпадения по
   названию уйдёт в `must_have_unmet`, хотя ИИ мог бы его перевести. Если нужно, модель может
   присылать нормализованную категорию (сделать при подключении к `build_trip`).
2. **Средняя.** Если пожелание — и категория, и неточное имя («Музей, которого нет»), побеждает
   категория: турист получит популярные музеи, а не «unmet». Это осознанный компромисс.
3. **Низкая.** Пул читается по `LIMIT 5000` самых популярных мест; для Алматы достаточно,
   при росте базы пересмотреть.
4. **Низкая.** Веса — первые значения, на реальных данных не настраивались; «память» принимает
   отображение категорий, формат Ф12 может измениться.
5. **Не проверялось:** на полной базе OSM (только фикстуры); качество подбора на реальных брифах.
