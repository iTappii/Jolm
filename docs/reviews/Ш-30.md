# Ревью Ш-30 — гостевой чат

`POST /v1/chat/guest` отдаёт `text/event-stream`. Гость присылает историю сам, сервер ничего не
хранит: ни сообщений, ни счётчиков. Гостевой промпт (`guest.<locale>.v1`), единственный инструмент —
`search_places` (тот же SQL `PLACES_SEARCH`, что и у `GET /v1/places`).

## Что сделано

- Тело: `{"messages": [{"role": "user"|"assistant", "content": "..."}], "locale": "ru"|"en"}`.
  Пределы: до 20 сообщений, до 2000 символов в сообщении, до 8000 всего, последнее сообщение —
  от пользователя, пустые/пробельные не принимаются → 422 `validation_error`. `locale`
  необязателен, иначе `Accept-Language`.
- События (`event: <name>\ndata: <json>\n\n`): `text_delta {"text"}`, `map_places {"reason":
  "search","places":[{id,name,category,lat,lon}]}`, `done {"usage":{input_tokens,output_tokens}}`,
  `error {"code","message"}`. Поток кончается ровно одним из `done` / `error`.
- `map_places` для гостя **отправляется** после каждого `search_places`, нашедшего места: карта
  показывает то, о чём идёт речь. Для зарегистрированных пины — только обязательные и выбранные
  (Ш-31), поэтому там `reason` другой.
- Цикл инструментов (`app/chat/engine.py`, общий с Ш-31): модель вызывает инструмент → сервер
  ищет → результат уходит как сообщение `tool` → стрим продолжается. До 3 раундов инструментов
  (гость), потом последний вызов идёт **без** инструментов, чтобы модель ответила текстом. До 6
  вызовов за раунд. Неверные аргументы и неизвестный инструмент возвращаются модели текстом
  ошибки, не 500.
- Лимиты: окно 1 час, 20 запросов на `X-Install-ID` и 60 на IP (`GUEST_CHAT_*` в
  `config.py`). Лимит считается только если запрос принят (422 лимит не тратит); если сработал
  любой из двух, не тратится ни один. Нет заголовка или он не UUID → только IP. 429
  `rate_limited` + `Retry-After`. Для этого `AppError` получил необязательные `headers`.
- **Где состояние лимитов.** В памяти процесса (`SlidingWindowLimiter`): гостевой чат не должен
  писать в БД, а запись счётчиков в таблицу — это запись. Ключи в памяти не пишутся никуда,
  память ограничена (50 000 ключей, старые вытесняются). `TODO(multi-instance)` в
  `ratelimit.py`: с несколькими процессами реальный предел умножается на их число.
- Токены: на каждый запрос создаётся свой `ResilientLLM`, счётчик не общий (замечание
  координатора к Ш-29). Если провайдер не настроен — 503 `llm_unavailable` до стрима и до учёта лимита.
- Новые ключи i18n: `rate_limited`, `llm_unavailable`, `llm_timeout`, `llm_error`, `chat_full`.
  Сообщение в `error` локализовано по `locale`; текст исключения провайдера клиенту не уходит.

## Проверки

- `server/.venv/bin/python -m pytest tests/test_chat_guest.py -q` — 35 тестов, прошли: порядок
  и формат событий, tool call → поиск → продолжение ответа (модель видит результат), пустая
  выдача, неверные аргументы (5 вариантов), неизвестный инструмент, предел раундов, 10 вариантов
  422 и граничный допустимый случай, 429 по install id / по IP при пустом и неверном
  заголовке / при смене install id, отказ (422) не тратит лимит, скользящее окно и вытеснение
  ключей, **БД не меняется** (число строк во всех таблицах `public` до и после, включая запрос
  с поиском и 422), `error` при ошибке провайдера (и после частичного текста), 503, usage
  на запрос, выбор языка.
- Живая проверка: `uvicorn` на 8765, `curl -N` с fake-провайдером вернул `text_delta` и `done`
  в нужном формате; `POST /v1/chats` без токена — 401.
- `make ci` — Ruff чисто, 408 тестов прошли, 1 пропущен (после Ш-31).

Совместимость с `SSEClient.swift` прочитана, не менялась: используются только поля `event:` и
`data:` в одну строку, пустая строка завершает событие.

## Замечания

1. **Средняя.** Лимиты в памяти: сброс при перезапуске, не общие между процессами. Приемлемо для
   v1 с одним процессом; перед масштабированием — общее хранилище.
2. **Средняя.** `client_ip` берёт адрес сокета. За обратным прокси все гости будут одним IP и
   упрутся в общий лимит 60/час — до деплоя нужен список доверенных прокси и `X-Forwarded-For`.
3. **Низкая.** Нет глобального потолка расходов на LLM: злоумышленник с множеством IP обходит
   лимиты. Нужен суточный бюджет токенов (после выбора провайдера, SSOT §16.12).
4. **Низкая.** Гость может подставить в историю любые реплики `assistant`; на безопасность
   это не влияет (инструмент только читает публичные данные), но промпт нельзя считать
   неотключаемым — защита от инъекций промпта не проверялась на реальной модели.
5. **Не проверялось:** поведение с реальной моделью; обрыв соединения гостем (нечего
   сохранять, цикл прекращается отменой задачи Starlette) отдельным тестом не покрыт.
