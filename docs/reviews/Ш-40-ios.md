# Ревью Ш-40 (iOS) — регистрация устройства для пушей

## Что сделано

- **`DeviceRegistrar`** (`Features/Devices/DeviceRegistrar.swift`) шлёт `POST /v1/devices` с телом `{"install_id", "apns_token", "language"}`. `install_id` — тот же, что в `X-Install-ID`; `language` — `ru` или `en` (то, что выбрал человек, а не язык системы вообще); `apns_token` — **всегда в теле**, `null`, пока iOS не выдал токен. Сервер (`server/app/devices/api.py`) принимает `null` (поле `Optional`, пустая строка тоже в `null`), токен — hex 32–200 символов; клиент шлёт 64 hex-символа в нижнем регистре.
- **Когда вызывается** (`RootView`): при запуске и при каждой смене `isSignedIn` (вход и выход — одним `.task(id:)`, значит и запуск, и после входа, и после выхода / удаления аккаунта); при смене языка; при новом токене APNs; при возврате приложения в активное состояние, если прошлый вызов не удался (`needsRetry`: нет сети, ошибка сервера). Вызовы выстроены в очередь: быстрые «вход → выход» доходят до сервера по порядку, каждый с состоянием своего момента (тест проверяет, что медленный вызов с токеном не обгоняет следующий без него).
- **Токен.** `JolAppDelegate` (`@UIApplicationDelegateAdaptor`) получает `didRegisterForRemoteNotificationsWithDeviceToken`, переводит в hex, сохраняет в `UserDefaults` (`jol.apns_token`) и сразу регистрирует; тот же токен второй раз — не новость. Ошибку регистрации (`didFailToRegister…`) игнорирует: без платного аккаунта она ожидаема, устройство остаётся с `null`.
- **Разрешение на уведомления.** Не при запуске. Системный вопрос задаётся один раз за жизнь установки, когда в чате впервые появляется поездка (`chat.tripID` из `nil` в значение, пользователь вошёл) — единственный момент, когда фраза «сообщим, если погода изменит план» уместна. Любой ответ окончательный (флаг `jol.push_asked`); «разрешить» → `registerForRemoteNotifications()`. На каждом запуске: если разрешение есть — токен запрашивается заново (iOS мог его сменить), если снято в Настройках — сохранённый токен сбрасывается и серверу уходит `null`; ничего не спрашивается.
- В UI-тестах и заглушке (`-JolStubAPI`, `-JolFakeSignedIn`) подставлен `UITestPush`: системный диалог не появляется.
- Entitlement `aps-environment` и push-возможность **не добавлены**: для них нужен платный Apple Developer Program, без него подпись на устройство не соберётся. Когда аккаунт будет — добавить `aps-environment` в `Jol.entitlements` и включить Push Notifications.

## Проверки

- Юнит `DeviceRegistrarTests` (8): гость — `null`-токен в теле, язык, без `Authorization`; вошедший — Bearer, после выхода — без него; новый токен — hex, 64 символа, отправка сразу, повтор того же токена без запроса, следующий запуск шлёт сохранённый; сбой запоминается и повторяется один раз; порядок быстрых вызовов; вопрос о разрешении — один раз и не при запуске, отказ не повторяется и токен не запрашивается; на запуске токен запрашивается заново при разрешении и сбрасывается при снятии (серверу уходит `null`).
- Ручная проверка запуска в симуляторе (`-JolStubAPI -JolStubSignedIn`, русский): заглушка записала в лог `POST /v1/devices auth=1`, тело `{language: ru, install_id: …, apns_token: null}`.

## Не сделано / не проверено

- **Реальный пуш на устройстве не проверен** (нужны платный аккаунт, ключ APNs, `aps-environment`). Не проверено, что системный диалог появляется в нужный момент на настоящем приложении: только юнит-тестом с подменой.
- Нет экрана настроек уведомлений (включить/выключить, перейти в Настройки iOS); отказавшему человеку приложение вопрос не повторяет.
- Нет обработки самого пуша (открытие чата/поездки по нажатию, перечитывание чата): сервер ещё не присылает полезной нагрузки для клиента, отмечено в ревью Ш-40 (пункт 1).
- Токен хранится в `UserDefaults` (не секрет, сбрасывается с переустановкой, как `install_id`).

## Пробелы серверного API

- Ответ `push_enabled` клиент не показывает и не использует. Нет способа «отвязать» устройство без запроса от этого же `install_id` (нужен для выхода с другого устройства) — не требовалось.

## Перепроверка (2026-11-21, независимо от автора)

- **Контракт.** `POST /v1/devices` есть в `server/app/devices/api.py`: тело `{install_id: uuid, apns_token: hex 32–200 | null, language: ru|en}` (`DeviceRegistration` шлёт ровно эти три ключа, `apns_token` всегда, `null` пока токена нет), ответ `{install_id, user_linked, push_enabled}`; `Authorization` необязателен — гость пишет строку без привязки к пользователю, поэтому повторный вызов на выходе из аккаунта корректно отвязывает устройство. Просроченный access-токен даёт 401, который `APIClient` лечит refresh-ом и повтором.
- **Когда вызывается.** `RootView`: `.task(id: isSignedIn)` (запуск, вход, выход), смена языка, возврат в активное состояние при `needsRetry`; запросы идут цепочкой, порядок сохраняется. Системный вопрос про уведомления — один раз после первой поездки, не при запуске.
- **DoD** («пуш приходит на устройство, ручная проверка») **не проверен и не может быть** без платного Apple Developer Program и ключа APNs (в плане шаг остаётся `[~]`); проверена только регистрация (юнит и заглушка).
- Нашёл ли ошибки: **нет**.
