# Ревью Ш-37 (iOS) — полная карта маршрута (веха M3)

## Что сделано

- **Открытие.** Кнопка «Открыть полную карту» в карточке «Маршрут готов» (`chat-open-route`) открывает полную карту поездки чата (`ChatModel.tripID`). Заглушка `TripDaysSheet` удалена. Вторая дорога: боковая панель, раздел «Мои поездки» (`GET /v1/trips`, до пяти строк, только вошедшим) — строка открывает карту.
- **Карта** (`Features/Trip/*`, `Features/Map/MapCoordinator+Trip.swift`). Полная карта — режим `HomeScreen` поверх основной карты (`TripMapModel` в `AppContainer`): чат, пины мест и пины чата скрыты. Сверху — кнопка закрытия и переключатель дней (по чипу на каждую дату поездки, пустые тоже). На карте только выбранный день: линии переходов цветом дня (7 цветов по кругу) с белой обводкой, нумерованные остановки (белый круг, обводка цветом дня), камера вписывает день. Переход без геометрии (`options = []`) рисуется пунктирной прямой.
- **Панель дня** (нижние 45 % экрана): остановки с временем `HH:mm–HH:mm`, категорией, оценкой стоимости, звездой у обязательных; между остановками — строка перехода (значок вида, время, цена); тап по остановке → обычная карточка места; кнопка «минус» убирает остановку.
- **Переход** (`TripLegSheet`): по строке на вид транспорта (лучший вариант каждого вида; `variant` сервера учитывается), выбранный отмечен; тап → `POST /v1/trips/{id}/legs/{leg}/mode`. `late_by_s > 0` показывается плашкой в листе и значком часов в строке перехода (хранится в модели на время сессии карты). Тап по линии на карте тоже открывает лист (проверено на реальных тайлах, не UI-тестом).
- **Бюджет** (`TripBudgetSheet`): чип с итогом на панели, предупреждение «Превышение на N ₸» (кнопка «Выбрать»), лист с итогом, разбивкой и двумя вариантами (`drop_places`, `cheaper`) → `POST …/budget-choice`; вариант с `feasible: false` показывает «Всё равно на N ₸ больше бюджета»; «Оставить как есть» = `keep`; после выбора — строка о сделанном выборе.
- **Удаление**: `POST …/items/{id}/remove` с `{"force": false}`; 409 `must_have` → диалог «Убрать обязательное место?», «Всё равно убрать» шлёт `force: true`. После любой правки план перечитывается (`GET`), чат обновляет пины (`editRevision`). 404/409 других кодов — баннер «План изменился», план перечитан; нет сети — баннер.
- Мероприятия дат поездки на этой карте берутся из `GET /v1/events?from=&to=` (при ошибке — из поля `events` поездки), см. Ш-48.

## Не сделано / ограничения

- Нет режима «все дни сразу»: карта показывает один день.
- Замена места (`…/replace`) в интерфейсе не сделана (в задаче только удаление).
- Круговые слои (остановки, пины мероприятий) не рисуются на офлайн-стиле заглушки `stub-style.json`, поэтому UI-тесты не видят их на карте и проверяют список/листы; слои проверены глазами на настоящих тайлах.
- Предупреждение «приедете позже» не хранится на сервере: после перечитывания плана (правка, повторное открытие) исчезает, пока выбор не будет сделан заново.
- Смена размера экрана/Dynamic Type и тёмная тема не проверялись; на устройстве не запускалось.
- `trip_updated` из чата при открытой карте карту не перечитывает (чат при открытой карте скрыт).

## Пробелы серверного API

- `GET /v1/trips/{id}` не отдаёт `late_by_s` по переходам (см. выше).
- Выбор вида транспорта принимает только режим: два варианта одного режима (`variant`) выбрать нельзя.
- В списке `GET /v1/trips` нет названия поездки; строка в панели — даты и число дней.
