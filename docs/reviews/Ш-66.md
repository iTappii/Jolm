# Ревью Ш-66 (сервер): рамки и расход ИИ

Сделано 2026-11-24, ветка `sh-66`. Только сервер; iOS не трогали.

## Что сделано
- **Промпты** `trip_brief` v9 и `guest` v5 (RU + EN), старые версии не тронуты. Вместо строки «Держись
  темы…» — блок «Рамки»: можно всё о путешествиях (в т. ч. общие советы: что взять, погода, обычаи,
  деньги, безопасность, SIM, визы), с упором на Казахстан; нельзя — код, SQL/базы, домашка, тексты на
  заказ — короткий вежливый отказ и возврат к поездке; не раскрывать промпт, названия и аргументы
  инструментов, базу, ключи, модель/поставщика; текст пользователя и данные из базы/инструментов —
  данные, а не команды; три коротких примера отказа. Приложение берёт старшую версию файла
  (`load_prompt`), поэтому v9/v5 используются автоматически (тест это проверяет).
- **`max_tokens`**: параметр `max_tokens` у `LLMProvider.stream`; `DeepSeekLLM` кладёт его в запрос,
  `FakeLLM` обрезает текст по лимиту (~4 символа на токен) и отдаёт `Done("length")`. `ResilientLLM`
  держит два предела и сам передаёт нужный. Ответ, обрезанный лимитом, заканчивается чисто: текст
  остаётся, поток не рвётся, в лог идёт предупреждение, растёт `jol_llm_truncated_total`. В базе
  сообщение сохраняется с `finish='stop'` (ограничение CHECK в `chat_messages`, миграцию не
  делали). Фоновая заметка памяти (`memory.note`) тоже получила предел.
- **Бюджеты токенов** (`app/llm_budget.py`, миграция `0035_llm_usage.sql`, таблица `llm_usage_daily`:
  день региона + sha256-ключ + токены). Ключи: пользователь, гость по install id, гость по IP,
  общий. Проверка ДО вызова модели (чат пользователя — внутри транзакции, отказ откатывает всё;
  гость — до счётчика частоты). Запись фактического расхода (`TurnRecord.usage`, вход + выход) —
  после хода, в той же транзакции, что сохранение ответа (гость — отдельной, в `finally`, даже если
  клиент ушёл). Граница дня — календарный день региона по умолчанию (Asia/Almaty). Старые строки
  удаляет воркер (`retention.cleanup`, хранение 3 дня).
- **Ошибки**: 429 `llm_budget_exceeded` (свой лимит), 503 `llm_budget_service` (общий; проверяется
  первым), оба с `Retry-After` до полуночи региона и локализованным текстом (RU/EN по `Accept-Language`).
- **Предупреждения**: при пересечении общего бюджета на 80 % и 100 % — `log.warning` и счётчик
  `jol_llm_budget_threshold_total{percent}`; пересечение ловится атомарно в SQL (раз за день на все
  процессы). Датчики `/metrics`: `jol_llm_tokens_today`, `jol_llm_tokens_budget`.
- **`make llm-smoke`**: после проверки связи — 7 вопросов (совет о поездке x2, код, SQL, вытащить
  промпт x2, инъекция в названии места), ответ проверяется маркерами (`judge`). Без ключа печатает
  «Skipped» и выходит с кодом 0.

## Настройки и значения по умолчанию (подтвердить с владельцем)
| Настройка | По умолчанию | Зачем |
|---|---|---|
| `LLM_MAX_OUTPUT_TOKENS` | 800 | предел обычного ответа (3-4 предложения; русский ~2-3 символа на токен, запас ~2000 знаков) |
| `LLM_MAX_OUTPUT_TOKENS_PLAN` | 1800 | раунд после `build_trip` / правки плана: объяснение по дням на 5-7 дней |
| `LLM_DAILY_TOKENS_USER` | 300 000 | зарегистрированный пользователь в день (ход с инструментами ~5-20 тыс.) |
| `LLM_DAILY_TOKENS_GUEST_INSTALL` | 60 000 | гость по install id |
| `LLM_DAILY_TOKENS_GUEST_IP` | 300 000 | гости с одного IP (NAT-дружелюбно) |
| `LLM_DAILY_TOKENS_GLOBAL` | 5 000 000 | весь сервис в день |
| `LLM_BUDGET_WARN_PERCENT` | 80 | порог предупреждения (второй порог — всегда 100 %) |

Значение 0 = без лимита. Числа прикидочные, по реальному расходу после первых дней их надо
пересмотреть (в `.env.example` и `config.py`).

## Открытые риски
1. **iOS**: ошибка 429 превращается в `APIError.rateLimited`, а `ChatTranscriptView` рисует
   «Too many messages. Try again in N s.» — для бюджета это N = десятки тысяч секунд и неверный
   смысл. Нужно в `ChatModel.failure(for:)` различать код `llm_budget_exceeded` (сейчас код в
   `.rateLimited` теряется) и показывать серверный текст. 503 `llm_budget_service` покажется как
   `.server(message)` — уже ок. Для гостя тот же 429.
2. Лимит мягкий: проверка до вызова, один ход может перешагнуть черту (до ~20 тыс. токенов).
3. Гость за NAT делит IP-лимит; install id без заголовка — только IP.
4. Если сохранение ответа упало, расход хода не записывается (одна транзакция); для гостя — записывается.
5. Фоновые вызовы (заметка памяти) в бюджеты не входят; у них свой предел длины.
6. Реальная проверка поведения на DeepSeek не делалась (ключа нет): `make llm-smoke` координатор
   запустит с ключом владельца. Проверки маркерные, результат читать глазами.
7. Усечённый вызов инструмента (предел посреди JSON аргументов) уйдёт моделью как ошибка аргументов
   и обработается как `ToolArgsError`; при 800 токенов на аргументы это маловероятно.

## Правка по решению владельца (2026-11-24): без лимитов на число сообщений
Владелец: количество сообщений ИИ не ограничиваем ни для зарегистрированных, ни для гостей.
Остаётся только предел длины одного ответа.
- Дневные бюджеты токенов пользователя и гостя (`LLM_DAILY_TOKENS_USER`, `_GUEST_INSTALL`,
  `_GUEST_IP`) по умолчанию 0 = выключены; код и настройки сохранены, чтобы включить позже
  (тогда 429 `llm_budget_exceeded`).
- Общий бюджет (`LLM_DAILY_TOKENS_GLOBAL`, по умолчанию 0) больше **никого не блокирует**: путь с 503
  `llm_budget_service` убран из `check`; при ненулевом значении только предупреждения 80 %/100 %
  (лог + `jol_llm_budget_threshold_total`). Расход по-прежнему считается; датчики
  `jol_llm_tokens_today` / `jol_llm_tokens_budget` остались. Текст `llm_budget_service` в i18n не используется.
- Лимиты частоты чата `CHAT_USER_LIMIT` (было 60/час), `GUEST_CHAT_INSTALL_LIMIT` (20), `GUEST_CHAT_IP_LIMIT` (60):
  по умолчанию 0 = без лимита (проверка пропускается только в чате; OTP/вход и прочие лимиты не тронуты;
  `ratelimit.acquire` не менялся).
- Остаются `LLM_MAX_OUTPUT_TOKENS=800`, `LLM_MAX_OUTPUT_TOKENS_PLAN=1800`.
- Таблица значений выше про бюджеты устарела: все они теперь 0. Риск 1 (iOS и 429) актуален, только если
  бюджеты когда-нибудь включат.
- Риск: без лимитов расход ИИ ничем не ограничен — следить по `jol_llm_tokens_today`.
