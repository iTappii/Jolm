# Ревью Ш-44 (iOS) — отправка контента и отзывы

## Что сделано

- **Одна точка входа.** На карточке места (только места нашей базы, не карточки адреса/точки из Ш-23c) — кнопка «Добавить данные» на вкладке «Обзор» и «Написать отзыв» на вкладке «Отзывы». Гость получает гейт регистрации (как у избранного и бронирования), форма открывается только после входа.
- **Форма** (`ContentSheet`): выбор типа из пяти серверных — отзыв (оценка 1–5 звёздами + текст), меню (блюда с ценами и/или фото меню), фото (+подпись), данные о транспорте (номер маршрута, остановка, направление, интервал, цена проезда, примечание), цена входа (сумма, тип билета, примечание). Ошибки заполнения показываются на форме по лимитам сервера (`SubmissionDraft.problems`, зеркало `server/app/submissions/schemas.py`), кнопка «Отправить» неактивна, пока форма неверна.
- **Фото** (`PhotoSanitizer`, `PhotosPicker`): байты из пикера декодируются, ставятся «вертикально», уменьшаются до 2048 px по длинной стороне, рисуются в новый непрозрачный битмап и кодируются в JPEG без метаданных; затем из заголовка вырезаются все application-сегменты, кроме JFIF (`APP0`) и цветового профиля (`APP2`), — ImageIO сам пишет в файл небольшой блок EXIF (размер, цветовое пространство), без геоданных, но «нет EXIF» проще обещать и проверять на байтах. Размер ≤ 7 МБ (сервер принимает 8 МБ), качество снижается ступенями.
- **Поток отправки** (`ContentModel`, `ContentService`): `POST /v1/uploads {content_type: "image/jpeg", size_bytes}` → `PUT` на `url` из ответа с заголовками из ответа и ровно этими байтами (`APIClient.upload`: без токена и `X-Install-ID`, только `https`, `http` — только для loopback) → `POST /v1/submissions {type, place_id, payload}`; `place_id` шлётся и для `transit`. Стадии показаны на кнопке («Готовим фото…», «Загружаем фото…», «Отправляем…»). Повторная отправка после сбоя не берёт новый слот загрузки (слот — суточная квота, 40).
- **Результат** (SSOT §10.2): «Спасибо! Опубликовано, проверим позже. Бонус придёт после проверки». Ответ 201 со статусом `rejected_auto` — отдельный экран «Не прошло автоматическую проверку… бонус не начислен», не ошибка сети. Ошибки: `already_submitted` («Вы уже оставляли здесь отзыв»), `invalid_image`/`upload_not_found`/`upload_used` («Сервер не принял фото»), 429, сеть.
- **Вкладка «Отзывы»** (`ReviewsModel`, `PlaceReviewsView`): `GET /v1/places/{id}/reviews?limit=20&cursor=`; средний балл и число («4,5 · 2 отзыва»), строки со звёздами, текстом, датой, автором (`author_name` сейчас всегда `null` → «Аноним») и пометкой «· проверим позже» при `pending_review`; страницы по `next_cursor` при показе последней строки, повторы по `id` отбрасываются; пустое состояние `place-reviews-empty` сохранено; после отправки отзыва список перечитывается.
- **Заглушки** (`UITestContentStub`, `-JolStubAPI`): отзывы у фикстурного кафе (два), у музея нет; слот загрузки с `http://localhost:8000/...`, `PUT` отвечает 200; `POST /v1/submissions` — 401 без сессии, 201 `published_pending_review`, текст «spam» → `rejected_auto`, «again» → 409 `already_submitted`.
- Строки RU+EN (каталог): добавлено ~60 ключей, «%lld reviews» со склонениями.

## Замечания (по важности)

1. **Высоко (не проверено).** Реальная загрузка в S3-совместимое хранилище не проверялась: `PUT` проверен только заглушкой и юнит-тестом формы запроса; серверный `S3Storage` сам ни разу не работал с настоящим бакетом (ревью Ш-44 сервер, замечание 1). До TestFlight нужен один прогон «фото → бакет → публичный URL» целиком, в том числе проверка, что подписанные заголовки (`Content-Type`, `Content-Length`) совпадают с тем, что шлёт `URLSession`.
2. **Средне.** Выбор фото через `PhotosPicker` в UI-тестах не гоняется (системный пикер вне процесса приложения); весь путь после выбора покрыт юнит-тестами с реальными байтами изображения, а сам выбор и стадии «Готовим/Загружаем» на экране — только вручную.
3. **Средне.** Индикатор — стадии без процента: `URLSession.upload` не отдаёт прогресс в этом вызове. Для фото до 2048 px (обычно 0,3–1,5 МБ) этого достаточно; процент — отдельная доработка (делегат сессии).
4. **Средне.** Меню, цены и данные о транспорте на карточке не появятся, пока их не одобрит модератор (ответ сервера); форма об этом говорит общей фразой «проверим позже», отдельного «моих отправок» (`GET /v1/me/submissions`) в приложении пока нет.
5. **Низко.** `author_name` сервер пока не заполняет, поэтому у всех отзывов «Аноним».
6. **Низко.** Выбранный тип и введённый текст не сохраняются, если закрыть форму; отправка идёт только из открытого листа (при уходе в фон загрузка не продлевается).
7. **Низко.** Фото всегда JPEG (PNG/WebP/HEIC из пикера перекодируются): прозрачность теряется (белый фон), live-фото берётся как кадр.
8. **Низко.** Название места в форме берётся из карточки; для `transit` место не обязательно по серверу, но на карточке оно всегда есть, поэтому передаётся.
9. Найдено при написании тестов: ImageIO пишет блок EXIF в JPEG даже без метаданных — исправлено вырезанием application-сегментов (см. выше).
