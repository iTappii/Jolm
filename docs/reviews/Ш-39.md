# Ревью Ш-39 — клиент Open-Meteo и кэш

`WeatherProvider` поверх Open-Meteo Forecast API, кэш в БД, адаптер к интерфейсу прогноза
планировщика. В `build_trip` и чат прогноз **не подключён** (подключение и перепроверка — Ш-40).

## Что сделано

- **Интерфейс** `server/app/providers/weather/base.py`: `WeatherProvider.forecast(lat, lon,
  days, elevation_m=None) -> {date: DayWeather}`; `DayWeather.hours` — 24 локальных часа
  (Asia/Almaty), `HourWeather(temperature_c, precipitation_probability 0..1, precipitation_mm,
  wind_kmh, weather_code WMO)`. Дни вне прогноза в ответе отсутствуют; `WeatherUnavailable`,
  если не удалось получить ничего.
- **Клиент** `providers/weather/open_meteo.py`: почасово `temperature_2m,
  precipitation_probability, precipitation, wind_speed_10m, weather_code`, `timezone=Asia/Almaty`,
  `start_date`/`end_date`. Для гор (`elevation_m` места) отправляется точка **и** высота
  (`elevation`, округление до 100 м) — температура корректируется на высоту.
- **Кэш — таблица `weather_cache`** (миграция `0013_weather_cache.sql`), а не память процесса:
  общий для API и воркера (Ш-40), переживает перезапуск, не тратит квоту на каждый процесс.
  Ключ: координата с округлением до 0,01° (≈1 км; запрос уходит по округлённой точке, чтобы
  данные соответствовали ключу), высота (−1 = не передавалась), локальный день. TTL 3 часа
  проверяется при чтении по `fetched_at`; недостающие дни запрашиваются **одним** запросом на
  диапазон. Сбой API: до 24 часов отдаются устаревшие дни; нет и их — `WeatherUnavailable`.
  Горизонт 16 дней (сегодня + 15), прошлые дни и дальше — «неизвестно», запросов нет. Соединение
  с БД на время HTTP не держится. Персональных данных и ссылок на места в таблице нет (правило 8
  не применяется).
- **Адаптер** `ForecastView` реализует `planner.weather.Forecast` (`rain_probability(day, hour)`);
  `city_forecast(provider, days)` даёт `ForecastView` по центру Алматы или `UnknownForecast` при
  сбое (план тогда строится без погоды, как сейчас). Правило дождя часа: вероятность Open-Meteo;
  если её нет — по количеству осадков (≥ 0,3 мм = дождь); гроза (WMO 95/96/99) — всегда дождь.
- `build_plan(..., forecast=None)` принимает прогноз (по умолчанию — неизвестный, поведение не
  меняется).
- Настройка `OPEN_METEO_API_KEY` (платный план): тогда запросы идут на
  `customer-api.open-meteo.com` с `apikey` (ключ не логируется). `OPEN_METEO_URL` уже была.

## Условия Open-Meteo (проверены 2026-11-21 на open-meteo.com/en/terms)

- Бесплатный API — **только некоммерческое использование**: < 10 000 вызовов в день, 5 000 в час,
  600 в минуту, лицензия CC BY 4.0 (нужна атрибуция), право блокировки за злоупотребление.
  Сайты и приложения с подпиской или рекламой считаются коммерческими.
- Jol зарабатывает на партнёрах (SSOT §12), поэтому для запуска нужен **платный план** — заложить
  в бюджет запуска (TECH_PLAN Ш-39) и выдать ключ `OPEN_METEO_API_KEY` до продакшена. Для dev и
  TestFlight с небольшим числом пользователей бесплатный API технически работает, но формально это
  не некоммерческий сценарий — решение за владельцем.
- Атрибуция «Weather data by Open-Meteo.com» — показать в приложении («О приложении»).
- Расход: один день одной точки ≈ 1 запрос на 3 часа; активная поездка в Алматы — единицы
  запросов в сутки на всех. Лимиты не опасны, дело в лицензии.

## Проверки

- `tests/test_weather.py`, 18 тестов, **без сети**: `httpx.MockTransport` отвечает записанным
  ответом (`tests/fixtures/open_meteo/almaty_center.json` — реальный ответ для центра Алматы на
  3 дня, и `medeu_elevation.json` — точка Медеу с `elevation=1700`; запросы без личных данных).
  Разбор ответа; округление ключа; параметры запроса; кэш по дням и общий между процессами;
  запрос только недостающих дней; TTL 3 ч (до и после); горы — отдельные ключи и `elevation`;
  горизонт; сбой с устаревшим кэшем (10 ч — отдаётся, 25 ч — ошибка); сбой без кэша; тело
  ошибки со статусом 200; платный хост и ключ; адаптер (`rain_probability` по часам, неизвестные
  часы, гроза, осадки без вероятности); `city_forecast` при недоступном провайдере.
- `make migrate` применён к dev-БД. `make ci`: 544 прошли, 1 пропущен, линтеры чистые.

## Не сделано / не проверено

- Прогноз не подключён к `build_trip` и правкам; решение, включать ли его по умолчанию (и тем
  самым сеть в сборке плана), — Ш-40 вместе с перепроверкой.
- Реальный платный хост и ключ не проверялись (нет ключа); проверено только по формату запроса.
- Живой запрос выполнен один раз вручную для записи фикстур (бесплатный API, без личных данных).
- Прогноз — один на город (центр Алматы), как требует интерфейс планировщика; для горных мест
  Ш-40 вызывает провайдер с точкой и высотой места напрямую.
- `.env.example` не дополнен `OPEN_METEO_API_KEY` (файл вне зоны задачи).
- Очистки старых строк `weather_cache` нет (строки перезаписываются; объём — единицы точек × 16 дней).
