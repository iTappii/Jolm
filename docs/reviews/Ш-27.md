# Ревью Ш-27 — вход по SMS

Номер приводится к E.164 при запросе и проверке одноразового кода. Для
казахстанских номеров можно опустить код страны или указать префикс `8` либо
`7`. Для других стран требуется явный международный формат с `+`. Неверный
формат даёт HTTP 422.

`SmsProvider` используется общим OTP-маршрутом. Заглушка разрешена только в
`dev` и `test` при явном выборе `SMS_PROVIDER=stub`. Она пишет код в локальный
лог без номера. Если провайдер не настроен или среда запрещает заглушку, запрос
завершается HTTP 503 до записи кода.

## Проверки

- `pytest server/tests/test_sms.py -q` на отдельной базе `jol_sms_test` с
  применением миграций — 24 теста прошли. Запрос кода на номер с префиксом `8`
  и проверка с `+7` создают одну телефонную учётную запись и рабочую сессию.
  Повторная проверка кода отклоняется. Запрос в `prod` с заглушкой даёт 503,
  код не попадает в лог и не записывается в БД.
- `ruff check server/app/auth/sms.py server/tests/test_sms.py` — чисто.

Проверка формата не определяет, существует ли номер или может ли он принимать
SMS. Реальный адаптер и проверка доставки остаются отдельной задачей после
выбора поставщика по SSOT §16.12.
