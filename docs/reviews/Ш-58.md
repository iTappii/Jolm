# Ревью Ш-58. Данные мест по регионам

Ветка `sh-58`, 2026-11-23. Реальный прогон: база `jol_s58`, регион «Казахстан». Отчёт о покрытии —
`docs/reviews/Ш-58-coverage.md`.

## Что сделано

1. **Регион «Казахстан»** (`db/migrations/0030_region_kazakhstan.sql`). Граница — внешний контур
   admin-границы страны (`admin_level=2`, KZ) из PBF Geofabrik, упрощённый до 1046 точек
   (допуск 0,02°, около 2 км). Это `Polygon` (колонку менять не пришлось). Центр 48,02 / 66,92, зум 4,5.
   `is_default` остался у `almaty`. Граница приблизительная по краю: места у самой границы страны
   могут попасть внутрь или выпасть на пару км.
2. **Импорт по границе региона** (`data/places/run_import.py --region <id> --source osm|overture|foursquare|all`).
   - Границу берёт из таблицы `regions`: bbox отсекает грубо, `ST_Covers` по полигону — точно
     (Ташкент и Нафталан внутри bbox страны, но отброшены).
   - OSM: переиспользован `data/osm/import_places.py` (`collect(..., keep=...)` фильтрует по границе до
     склейки дублей). Прежний запуск без `--region` работает как раньше.
   - Overture и Foursquare: `fetch_overture.py` (DuckDB, публичное S3-зеркало), читатели Parquet в
     `open_sources.py`, категории в `open_categories.py` (таксономия Overture, `fsq_category_labels`
     Foursquare → категории проекта). Не отображаются: магазины, услуги, школы и т. п.; места
     поклонения не берутся из этих наборов (тысячи мелких, в OSM — только с wiki-ссылкой).
   - В `Makefile`: `places-fetch`, `places-import`, `places-coverage`.
3. **Склейка дублей между источниками** (`place_match.py`, `place_load.py`).
   - При импорте записи: известный внешний id → то же место; иначе соседнее место другого источника
     (до 100 м, парки до 400 м), совместимая категория (еда, жильё, музеи, зелень, наследие — группы)
     и похожее название (транслитерация RU/KK → латиница, без слов «кафе/ресторан/hotel…», точное
     совпадение, вхождение или `difflib` ≥ 0,85) → привязка и дозаполнение; иначе новое место.
   - Второй заход `cross_dedupe(region)`: места разных источников, которые остались отдельными
     строками (например, Overture загрузили до OSM), склеивает `merge_place`; выживает строка OSM.
     Запись одного источника с другой записью того же источника не склеивается.
   - Внешние id: таблица `place_external_ids (source, external_id, place_id)`; OSM по-прежнему в
     `places.osm_type/osm_id`.
   - `merge_place` (правило 8) расширен: переносит `place_external_ids` и `place_field_sources`,
     добавлен `phone`; поле, чей источник manual/partner/user, переходит к выжившему как ручное.
     Тест в `test_places_regions.py`.
4. **Источник у каждого поля** (`db/migrations/0031_place_sources.sql`).
   - Таблица `place_field_sources (place_id, field, source, updated_at)`, поля: названия RU/EN/KK,
     адреса, сайт, телефон (новая колонка `places.phone`), категория, координаты, часы.
     Для пользовательской цены входа тоже пишется `user`.
   - Приоритет — SQL-функция `source_rank`: manual = partner (5) > user (4) > osm (3) > overture (2) >
     foursquare (1). Повторный импорт пишет поле, только если источник текущего значения того же
     или более низкого ранга; manual/partner/user не затираются никогда; значение без источника
     меняется, только если пустое. `places.manual_override` оставлен как был (админка, curated CSV) и
     проверяется вместе с источниками.
   - Где ставится источник: админка (`manual`), `import_popular.py` (`manual`), модерация цены входа
     (`user`), импорт OSM (`osm`), импорт Overture/Foursquare. Партнёрская правка в коде пока не
     существует; ранг `partner` и защита готовы.
   - Миграция проставила источники существующим местам: поля из `manual_override` и места без
     OSM-объекта — `manual`, остальные — `osm`.
5. **Отчёт о покрытии**: `make places-coverage REGION=kazakhstan [OUT=файл]`
   (`data/places/region_coverage.py`) — по категориям (часы, цены, фото, телефон, сайт), по
   источникам, склеенные места, чьё значение у каждого поля. Деление по городам и областям не
   сделано: в базе нет административных границ.
6. **Атрибуции (iOS)**: на экране «О приложении» рядом с OpenStreetMap добавлены строки Overture Maps
   Foundation (CDLA-Permissive-2.0) и Foursquare OS Places (Apache 2.0), RU/EN в `Localizable.xcstrings`,
   идентификаторы `about-overture`, `about-foursquare`, UI-тест проверяет их.
7. Тесты, регион в `test_regions.py` обновлены (регион Казахстан, точка внутри страны теперь даёт
   `kazakhstan`; в `/v1/regions` теперь два региона, по умолчанию — Алматы).

## Не проверено и что нужно от владельца

- **Foursquare OS Places не загружен.** Набор на Hugging Face теперь с закрытым (gated) доступом:
  нужен аккаунт и токен, регистрироваться я не стал. Читатель `read_foursquare` и сопоставление
  категорий покрыты тестами на фикстуре с официальными колонками (`fsq_place_id`, `name`, `latitude`,
  `longitude`, `fsq_category_labels`, `date_closed`, `tel`, `website`, `address`), но на реальном файле
  не запускались. Чтобы загрузить: получить доступ к `foursquare/fsq-os-places` на Hugging Face,
  скачать Parquet-файлы Казахстана (фильтр `country = 'KZ'`) в один файл
  `data/places/cache/foursquare-places.parquet`, затем `make places-import REGION=kazakhstan SOURCE=foursquare`.
- Качество склейки измерено на фикстурах, а не вручную по реальным парам: порог названия и радиусы
  выбраны консервативно (лучше оставить дубль, чем потерять место). Стоит выборочно посмотреть
  пары в крупных городах.
- Overture из-за bbox тянет Россию, Узбекистан и т. д. (отсекаются границей); на скачивание уходит
  около 14 секунд.
- Граница страны упрощена на ~2 км; для точной обрезки (например, отдельный регион «область») нужны
  свои полигоны.
- Деление отчёта по городам и областям не сделано.
- Партнёрский источник (`partner`) пока нигде не пишется — появится вместе с кабинетом партнёра.
- Алматинский регион и прежние тесты работают (полный прогон зелёный); импорт Алматы без `--region`
  (`make import-osm`) по-прежнему использует старый bbox.
