## Отклонения от плана (приняты как временные)

| Что | Почему | Что нужно |
|---|---|---|
| Python 3.9 вместо 3.12 (`requires-python >=3.9`, ruff `py39`) | На машине только системный 3.9.6 | Поставить Python 3.12 (`brew install python@3.12` или `uv`), поднять `requires-python` и `target-version`, пересоздать venv |
| Postgres на порту 5433 | 5432 занят другим процессом | Оставить, задокументировано в `.env.example` |
| `postgis/postgis:16-3.4` под эмуляцией amd64 | Нет arm64-образа | Для скорости на Apple Silicon позже рассмотреть arm64-сборку PostGIS |
| В `jobs` добавлен `dedupe_key` | Нужен для идемпотентной постановки периодических задач | Норм — дописать в `TECH_PLAN.md §5` при следующей правке модели |

## Замечания

| # | Важность | Замечание | Что сделано / что нужно |
|---|---|---|---|
| 1 | средняя | Тестовая фикстура делает `DROP DATABASE … WITH (FORCE)` по имени из `TEST_DATABASE_URL`. Если по ошибке указать там рабочую базу — она будет удалена | **Исправлено**: защита — удаляются только базы с суффиксом `_test` / `_scratch` |
| 2 | средняя | Воркер выполняет всю пачку задач в одной транзакции: обработчик с внешним эффектом (пуш, HTTP к Open-Meteo, LLM) держит транзакцию и блокировки всё время работы; при падении после отправки пуша транзакция откатится и пуш уйдёт повторно. «Ровно один раз» гарантируется только для записей в БД | Пока обработчиков с внешними эффектами нет — принято. **Перед Ш-40** (погода/пуши): брать задачу с коротким `locked_at`-арендованием и коммитом, внешние вызовы — вне транзакции, идемпотентность пушей через `notifications.sent_at` |
| 3 | низкая | Если обработчик роняет процесс целиком (OOM), `attempts` не растёт → такая задача будет падать бесконечно | Решается тем же арендованием из п.2 (увеличивать `attempts` при захвате) |
| 4 | низкая | `MARK_CLAIMED` (`locked_at = now()`) внутри той же транзакции бесполезен — другие его не видят до коммита | Уйдёт вместе с п.2 |
| 5 | низкая | Язык ошибок по умолчанию — английский (`DEFAULT_LOCALE = "en"`); в SSOT не определено | Оставлено; если основной язык RU — поменять одну константу в `app/i18n.py` |
| 6 | инфо | `jobs.cleanup` через 14 дней удаляет и «мёртвые» задачи с ошибкой | Достаточно для v1; при появлении мониторинга — хранить упавшие дольше |
