# Ревью Ш-26 — Sign in with Apple

- Дата — 2026-11-21.
- Статус — в работе. Серверная часть DoD выполнена (тест подписи на фикстуре). Вход
  в симуляторе с тестовым Apple ID не проверен: нужен Apple ID и команда разработчика
  с включённой возможностью Sign in with Apple.

## Сервер

- `POST /v1/auth/apple/challenge` выдаёт nonce — подписанный JWT на 5 минут со случайным `jti`.
- `POST /v1/auth/apple` проверяет identity token: RS256, ключ по `kid` из JWKS Apple,
  `iss=https://appleid.apple.com`, `aud=APPLE_CLIENT_ID` (строго одна аудитория), `exp`, `sub`
  и `nonce`. Nonce должен быть живым challenge Jol, иначе 401 ещё до запроса ключей — неизвестный
  `kid` не даёт заставить сервер ходить в Apple.
- Одноразовость: хеш nonce записывается в `apple_consumed_challenges` (миграция `0007`),
  повтор того же токена → 401. Токен с поддельной подписью challenge не тратит.
- JWKS кэшируется на час, обновление не чаще раза в 30 секунд; недоступность Apple → 503.
- `subject` = Apple user id. Почта из токена не сохраняется (может быть скрытой).

## iOS

- `AppleSignInView`: запрашивает challenge, передаёт его в `request.nonce`, отправляет
  identity token на сервер и сохраняет токены в `SessionStore`. Отмена закрывает шит,
  ошибка показывает «Попробовать снова». Тексты RU/EN в `AppleSignIn.xcstrings`.
- Entitlement `com.apple.developer.applesignin` в `Jol.entitlements` и `project.yml`.
- `JOL_API_BASE_URL` — в симуляторе `http://localhost:8000`, иначе только HTTPS.
- Временная кнопка профиля в левом нижнем углу карты открывает Apple-вход.

## Проверки

- `tests/test_apple.py` — 12 тестов: валидная подпись, повтор, другой `sub` с тем же nonce,
  поддельная подпись, 7 вариантов неверных claims, истёкший nonce и чужой алгоритм,
  ограничение запросов JWKS при неизвестном `kid` и при недоступности Apple.
- iOS: сборка в симуляторе проходит, `JolTests` — 4 из 4. UI-тест
  `AppleSignInUITests` (кнопка открывает шит) не запускался.

## Замечания

1. **Нет проверки DoD в симуляторе** — шаг остаётся `[~]`.
2. `AppleSignInView` сам собирает `URLRequest` вместо общего `APIClient` из Ш-14, а кнопка
   профиля ведёт прямо на Apple-вход вместо меню Ш-16. Это временно: перенести в `APIClient`
   в Ш-14 и в экран выбора способа входа в Ш-28.
3. При удалении аккаунта (Ш-28) App Store требует отозвать токен Apple через
   `appleid.apple.com/auth/revoke`. Для этого нужен authorization code и ключ Sign in with Apple —
   учесть в Ш-28.
