# Ревью: серверные долги (2026-11-21)

Закрыт остаток Ш-38 (погодный воркер маршрутизировал под блокировкой поездки) и разобраны
разделы «Ревью координатора» / «Замечания» всех `docs/reviews/*.md` на предмет открытых серверных
долгов.

## Что сделано

### 1. Погодный воркер: «рассчитать, затем применить» (Ш-38 №1, Ш-40 №3)

- `live/engine.py`: `find_proposal` заменён на `plan_proposal` — **только чтение**, без записей и
  без блокировки. Возвращает `Plan(version, expire, spec)`: версия плана, для которой он считался,
  список ожидающих предложений, которые нужно закрыть (старой версии плана или проблема исчезла из
  прогноза), и не более одного нового предложения. Маршрутизатор вызывается только здесь.
- `live/store.py::already_proposed` получил необязательный `ignore` (предложения, которые
  будут закрыты этим же планом, но в БД ещё `pending`).
- `live/jobs.py::weather_recheck`: прогноз → цикл до `RECHECK_ATTEMPTS = 3`: (1) транзакция без
  блокировки: читает поездку и считает план; (2) короткая транзакция: `FOR UPDATE` строки
  поездки, сравнение `version` с версией плана. Совпала — `_apply` делает одни записи (закрыть
  `expire`, создать предложение + сообщение в чат + push-задачу, поставить `weather_checked_at`).
  Не совпала — план пересчитывается. После трёх неудач — `TripChanged`: задача перезапускается
  воркером с отсрочкой, `weather_checked_at` не ставится (поездка остаётся «к проверке»).
- `_apply` под блокировкой дополнительно перепроверяет, что за время расчёта никто не создал
  ожидающее или уже решённое предложение на ту же остановку и день (две параллельные проверки
  одной поездки, `force`) — иначе предложение не создаётся (без «приставаний», без дублей).
- Тесты (`tests/test_live_plan.py`): все вызовы маршрутизатора раньше единственной блокировки;
  поездка изменилась во время расчёта один раз — пересчёт, ровно одно предложение
  `trip_version = 2`, две блокировки; поездка меняется всё время — `TripChanged`, ни предложений,
  ни push, `weather_checked_at` пуст, блокировок ровно `RECHECK_ATTEMPTS`; устаревший план не
  дублирует предложение, созданное параллельной проверкой. Как и в `test_trips_followups.py`,
  гонка имитируется изменением версии из маршрутизатора (тесты идут в одной транзакции и
  реальную конкуренцию строк не воспроизводят).

### 2. `hours_assumed` пересчитывается после правки (Ш-38 №2, часть)

`trips/edit.py::recompute_budget` теперь заново считает предупреждение `hours_assumed` (число
разных мест без часов работы среди пунктов плана) и обновляет/снимает его после удаления,
замены, переноса. Тест: `test_an_edit_recounts_the_hours_assumed_warning`.

### 3. Инфраструктура тестов

`tests/conftest.py::scratch_db_url`: имя временной БД для тестов миграций теперь производное от
имени тестовой БД (`<имя без _test>_migrate_scratch`), а не фиксированное `jol_migrate_scratch`.
Иначе два одновременных прогона на разных тестовых БД роняли бы друг другу тест миграций
(`DROP DATABASE … WITH (FORCE)`). Для `jol_test` имя то же, что и раньше.
