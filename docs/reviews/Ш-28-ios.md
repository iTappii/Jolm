# Ревью Ш-28 (iOS) — экраны входа и гейт регистрации

## Что сделано

- **Вход** (`Features/Auth/SignInEntryView.swift`, `SignInModel.swift`, `AuthService`): сегмент «Почта / Телефон», поле адреса (лёгкая проверка: почта вида `a@b.c`; телефон — 10–15 цифр, пробелы/скобки/дефисы убираются, `+` в начале сохраняется; номера KZ можно без кода страны, нормализует сервер) → `POST /v1/auth/otp/request` → экран кода: поле `.textContentType(.oneTimeCode)` (подсказка кода из SMS/Mail над клавиатурой), автоотправка на 6-й цифре, «Изменить», «Отправить снова через N с» (30 с; при 429 — `Retry-After`, без заголовка 60 с) → `POST /v1/auth/otp/verify`, токены в Keychain, `AuthState.refresh()`. Ошибки: неверный адрес (локально и 422), 429 (с обратным отсчётом, кнопка ждёт), неверный/просроченный код (401 `otp_invalid`, поле очищается), 503, нет сети, прочее.
- **Apple**: кнопка показывается выключенной с пояснением, пока `JOL_APPLE_SIGN_IN_ENABLED = NO` (`Config.xcconfig` → `Info.plist` → `AppConfig.appleSignInEnabled`, по умолчанию NO; описано в `ios/README.md`). В DEBUG есть аргумент `-JolAppleSignInEnabled`.
- **`APIError.rateLimited(retryAfter:message:)`**: `APIClient` теперь сохраняет заголовок `Retry-After` для 429 (обычный `.server` его терял). Для Ш-32 (чат, 429 с `Retry-After`) использовать этот случай.
- **Гейт регистрации** (`AccountGate`, `container.gate.requireAccount { … }`): вошедший выполняет действие сразу; гость видит лист входа («Войдите, чтобы построить маршрут. Ваше сообщение сохранено.»), действие выполняется после успешного входа и не выполняется при отмене. Подключён к отправке в чате (кнопка со стрелкой и «Отправить» на клавиатуре; черновик остаётся в поле; после входа показывается заглушка «Чат скоро появится», настоящий чат — Ш-32) и к кнопке «В избранное». Карточка места сама показывает лист (SwiftUI не умеет два листа с одного вида).

## Замечания

1. Сервер: 429 на `otp/request` без `Retry-After` (`server/app/auth/otp.py`, `AppError(429, "otp_rate_limited")` без headers) — клиент использует 60 с по умолчанию; стоит отдавать заголовок.
2. Нет различия «неверный» и «просроченный» код: сервер отвечает одинаково (`otp_invalid`), показывается общий текст.
3. Заглушка «Чат скоро появится» остаётся видимой после выхода из аккаунта (уйдёт с Ш-32).
4. Вход Apple не проверялся (нет платного аккаунта, Ш-26); SMS на реальном провайдере — нет (заглушка сервера, SSOT §16.12).
5. Первый ввод кода сразу после появления экрана в симуляторе один раз не запустил проверку (текст набран до готовности поля); повтор — работает. Не воспроизводилось в UI-тестах; к проверке на устройстве вместе с автоподстановкой из SMS.
