# Ш-64 (iOS). Чат не ждёт карту

## Что изменилось
- `ChatService.events(chatID:)` — поток `GET /v1/chats/{id}/events` (тот же SSE-разбор, что у сообщений).
- `ChatEvent.liveRouteStatus` (`building` / `ready` / `failed`; неизвестное состояние -> `.unknown`),
  `ChatState.liveStatus` / `isBuildingRoute`; `route_ready` сбрасывает статус.
- `ChatModel`: подписка на поток открытого сохранённого чата (`setEventsEnabled`, включается из `RootView`
  при входе + активном приложении; выключается в фоне и при выходе; `newChat` / `reset` / переключение чата
  останавливают). Переподключение 1 -> 2 -> 5 -> 10 с (потолок), счётчик сбрасывается после потока с событиями;
  задержка (`sleeper`) внедряется для тестов. Гость потока не имеет — поведение прежнее.
- `applyBackground`: `live_route` идёт через `ChatState.setLiveRoute`, равный маршрут ничего не меняет
  (ни версии, ни подгонки камеры, ни озвучки) — снимок при переподключении идемпотентен. После `route_ready`
  сохранённый живой маршрут игнорируется (не возвращает булавки поверх готового плана).
- Ввод не ждёт карту: `canSend` и `send` блокируются только пока идёт текст (`isStreaming`) — не менялись,
  добавлен тест, что отправка при `building` проходит.
- UI: капсула «Строю маршрут…» / "Building route…" (спиннер, VoiceOver «Строю маршрут…», Dynamic Type до xxxLarge,
  светлая/тёмная) в верхней полосе между кнопками сайдбара и профиля — ниже её закрывает карточка чата.
  `failed`: короткая надпись «Не удалось построить путь, попробую ещё раз при следующем сообщении» на 6 с, без alert;
  сбрасывается следующим сообщением.
- VoiceOver: новая точка живого маршрута озвучивается и вне `isStreaming`, если её принёс поток событий
  (`backgroundLiveVersion == liveVersion`); неизменный снимок молчит.
- Камера: фоновый `live_route` меняет `state.liveRoute`, дальше работает прежняя подгонка `MapCoordinator+Chat`.
- Заглушка API / демо: ответ на живой ход = `brief_updated` + `live_route_status building` + текст + `done`
  (без `live_route`); поток событий заглушки через 1,6 с (`-JolStubBuildDelay <с>` меняет) отдаёт `live_route` +
  `ready`; снимок при подключении — текущий маршрут. Фразы демо (chinese / president / bazaar / build) работают.

## Допущения о сервере (и поправки координатора)
- Любой `live_route` из потока трактуется как идемпотентный (сервер шлёт его и без изменений).
- `live_route_status` есть и в потоке сообщений — обрабатывается тем же редьюсером.
- Статус снимка может быть неточным — индикатор не опирается на него жёстко; `ready`/`live_route` придут следом.
- Если поток событий оборвался во время `building`, индикатор останется до следующего статуса/снимка
  после переподключения (снимок присылает статус).

## Открытые риски
- Индикатор на устройстве не проверен вживую против настоящего сервера (только заглушка).
- VoiceOver не прослушан на устройстве.
- Верхняя полоса узкая: на самых больших размерах текста капсула ограничена xxxLarge.
