# Ревью Ш-46 (iOS) — бонусы: баланс и история в профиле

## Что сделано

- **Меню профиля** (`ProfileMenuSheet`): вошедшему показана отдельная секция со строкой «Бонусы» (иконка подарка, справа баланс числом). Гость строки не видит. Баланс подгружается при открытии меню (`BonusModel.load`), пока грузится или при ошибке справа пусто.
- **Экран бонусов** (`Features/Bonuses/BonusScreen.swift`): крупный баланс, строка «1 бонус ≈ 1 ₸», строка «Траты бонусов: скоро» (с иконкой часов), ниже «История»: причина (отзыв / фото / меню / данные о транспорте / цена входа; неизвестный тип → «Бонус»), дата и `+сумма`. Пустая история — пояснение, что бонусы начисляет модератор после одобрения. Потянуть вниз — обновить. Ошибка первой загрузки — «Не удалось загрузить бонусы» и кнопка повтора.
- **Данные** (`BonusModel`, `BonusService`): `GET /v1/me/bonuses?limit=20[&cursor=…]` с токеном; страницы по `next_cursor`, когда на экране появляется последняя строка, подгружается следующая (повторы по `id` отбрасываются); ошибка следующей страницы даёт кнопку «Повторить», первая страница остаётся. Неудачное обновление не стирает баланс на экране. Без сессии модель запросов не делает.
- Курс берётся из ответа (`tenge_per_bonus`, по умолчанию 1); строка «1 бонус ≈ 1 ₸» — текст SSOT §10.3, не вычисляется.
- Заглушка для UI (`UITestExtraStub`): баланс 240, две записи (меню +188, отзыв +52).

## Проверки

- Юнит `BonusTests` (6): разбор страницы сервера и типов причин, неизвестный тип и дробные секунды в дате, запрос с токеном и `limit`, гость без запросов, вторая страница по курсору без повторов и без лишнего запроса при `next_cursor = null`, сбои (первая страница, следующая, обновление).
- UI `BonusUITests` (3, заглушка): строка «Бонусы» в меню показывает «240», экран показывает баланс, «1 bonus ≈ 1 ₸», «coming soon», две строки истории с причиной и суммой; русские строки («1 бонус ≈ 1 ₸», «Траты бонусов: скоро», «Меню»); у гостя строки нет.

## Не сделано / ограничения

- Траты бонусов — только надпись «скоро» (SSOT §16.8, на что тратить — открыто).
- Нет отдельного состояния «ожидает модерации»: сервер показывает только начисленное после одобрения (бонус за отправку, ещё не проверенную, в истории не виден).
- Нет напоминания о бонусах вне профиля (нет push о начислении).
- Dynamic Type, тёмная тема и настоящее устройство не проверялись.

## Пробелы серверного API

- В истории нет названия места или текста отправки, только тип (`submission_type`) и дата: «Меню» без указания, какое заведение.
- Нет статуса «на проверке» для отправок пользователя, поэтому нельзя показать «бонус придёт после модерации».
