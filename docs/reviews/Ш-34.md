# Ревью Ш-34 — раскладка по дням и времени

Модули `server/app/planner/`: `layout.py` (алгоритм и структуры плана), `hours.py` (часы работы,
длительность визита), `travel.py` (матрица времени и варианты переходов), `weather.py`
(интерфейс прогноза). Без модели, без случайности. В `build_trip` не подключено (Ш-36); бюджет и
жильё (Ш-35) не делались; новых таблиц и миграций нет (правило 8 не применяется).

## Структуры плана (в памяти; Ш-36 сохранит их)

`TripLayout(days, unplaced, warnings, start_point, start_point_default, travel_estimated)`.
`DayPlan(date, stops, legs)`; `Stop` -> `trip_items` (место, `kind` activity/meal, `meal`,
`start`/`end` в Asia/Almaty, `visit_min`, `must_have`, `hours_assumed`, `rain_exposed`);
`Leg` -> `trip_legs` (откуда/куда, `depart_at`, все `options` из Ш-22, `default_mode`,
`travel_s`, `estimated`). `Unplaced(place, reason, must_have)`; `LayoutWarning(code)`:
`travel_estimated`, `meal_missing`, `hours_assumed`. Вход: `plan_days(...)` или
`layout_selection(conn, selection, brief, travel, legs, forecast, start_point)`.

## Правила

- **Ёмкость дня** (`DAY_START`/`DAY_END`, активностей — `scoring.ACTIVITIES_PER_DAY`, те же
  числа, что размеры пулов Ш-33): calm 10:00–20:00 и 3; normal 09:30–21:00 и 4; dense
  09:00–22:00 и 6; плюс обед и ужин каждый день. Гора весит как две активности.
- **Кластеризация**: k = число дней, k-means с ограничением ёмкости (4 итерации, расстояние
  по прямой), зёрна — «самый далёкий первым». Обязательные ставятся первыми и могут превысить
  ёмкость, остальные — только в пределах. Начало дня — `start_point` или центр города
  (`ALMATY_CENTRE`), поскольку в брифе только `has_accommodation`; с явной точкой добавляется
  переход от неё к первой остановке, с центром по умолчанию — нет.
- **Порядок в дне**: ближайший сосед, приёмы пищи вставляются в лучшую позицию, затем 2-opt и
  перенос одной точки по ключу (нарушения, места под дождём, время окончания). Матрица —
  за интерфейсом `TravelMatrixProvider`: `RouterMatrix` (Valhalla, пешком и авто; плановое
  время = пешком, если до 15 мин, иначе авто + 5 мин ожидания) и `HaversineMatrix` для
  тестов. Valhalla недоступна или нет маршрута для пары -> оценка по прямой, `travel_estimated`.
- **Часы работы**: интервалы по дню недели с переходом через полночь (`hours.windows`, тест на
  согласие с `is_open_now`). `typical_visit_min`, иначе таблица по категории (`DEFAULT_VISIT_MIN`,
  гора 180). Нет часов -> 09:00–21:00 и `hours_assumed`.
- **Приёмы пищи**: обед 12:00–14:30 (60 мин), ужин 18:00–20:30 (75 мин). Обязательная кухня
  занимает слот первой; кофейни, пекарни, бары, клубы — не еда, а обычная остановка. Остальное
  — ближайшее к центру дня открытое место из пула еды; нет места -> `meal_missing`.
- **Горы**: на отдельный день, с наименьшей суммой осадков в первые часы дня; при неизвестном
  прогнозе — первый подходящий день; всегда первая остановка дня.
- **Дождь**: час дождливый при вероятности >= 0.5; необязательное outdoor-место не берётся в
  день, где дождливых часов >= 50% (если дождь везде и есть место — берётся, помечается
  `rain_exposed`); внутри дня outdoor-места уходят из дождливых часов.
- **Переход по умолчанию** = вариант `recommended` из Ш-22 (пешком до 15 мин, иначе минимум
  «время + 1 с за тенге»); для расписания резервируется верхняя оценка времени (пробки), плюс 5
  мин буфера. Вариантов нет -> время из матрицы, `estimated`.
- **Обязательные**: нет открытого дня -> `Unplaced("closed_on_trip_days")`; не влезло по времени
  -> сначала снимаются необязательные, затем `Unplaced("no_time")`. Молча не теряются.

## Проверки

- `tests/test_planner_layout.py`, 16 тестов: 1 день calm; 3 дня normal с китайской кухней и музеем
  в обязательных; 5 дней dense с горой, закрытым по понедельникам музеем и дождём 3 из 5 дней;
  разделение гор по дням и лучший прогноз; неизвестный прогноз; закрыт все дни; избыток
  обязательных; бар после полуночи и кофейня; окна и `is_open_now`; выбор перехода; недоступный
  Valhalla; явная точка начала; отсутствие часов; цепочка Ш-33 -> Ш-34 на БД; реальный Valhalla
  (запускался, так как был доступен). Инварианты: нет пересечений (с учётом перехода и
  буфера), место открыто в слоте, слоты еды, переходы есть, место не повторяется.
- `make ci`: 473 прошли, 1 пропущен.

## Не сделано / не проверено

- Реального прогноза нет (Ф11); интерфейс проверен только фиктивным прогнозом.
- Переходы между днями (жильё -> первая точка) — после Ш-35.
- Кластеризация по прямой, а не по матрице; веса и пороги не настроены на реальных данных
  Алматы. Реальный Valhalla проверен только на фикстурных местах, не на выборке из базы.
- Транзит в тестах не участвует (`network=None`); тарифы — тестовые.
- Пул еды мал -> `meal_missing`; повторное использование заведений между днями не разрешено.
- Если обязательное не влезло в день, оно не переносится на другой день автоматически.
- Допущения вынесены в `docs/adr/0003-open-defaults.md` (ждут владельца).

## Ревью координатора (2026-11-21)

`make ci` перезапущен — 473 прошли, 1 пропущен. 16 тестов покрывают эталонные брифы из DoD
(1 день calm, 3 дня normal с кухней, 5 дней dense с горой, выходной в понедельник, дождь),
часы через полночь, отказ Valhalla, реальный Valhalla. Обязательные места не теряются —
попадают в `unplaced` с причиной. Замечания:

1. **Средне.** Обязательное место, не влезшее в свой день, не переносится на другой день
   автоматически — только попадает в `unplaced`. Для туриста это «пожелание не выполнено», хотя
   свободное время в другие дни может быть. Доработать в Ш-36 (повторная попытка по дням).
2. **Низко.** Нет отдельного теста на детерминизм (один вход → один план); множества
   используются только для проверки принадлежности, но тест стоит добавить в Ш-36.
3. **Низко.** Пул еды не переиспользуется между днями — при маленьком пуле `meal_missing`.
   Можно повторять заведения с разной кухней — решить на реальных данных.
4. Транспорт в тесте с реальным Valhalla без общественного транспорта (`network=None`).
