# Ш-56. Пожелания вне зоны v1 — ревью

SSOT §5.4 («До запуска межгорода»), TECH_PLAN Ш-56. Только сервер: iOS причину в
`must_have_unmet` не разбирает, поэтому клиент не менялся.

## Что сделано

- **Справочник** `server/app/planner/outside.py`: 20 известных мест Казахстана вне рамки Алматы.
  Это Чарын, Кольсай (и Саты), Каинды, озеро Иссык, Тургень, Ассы, Конаев/Капчагай, Тамгалы,
  Алтын-Эмель, мавзолей Ясави, Туркестан, Отрар, Шымкент, Тараз, Астана, Бурабай, Балхаш,
  Байконур, Мангыстау и Актау.
  - У каждого места есть id, названия RU/EN, регион, примерная точка и основы слов для поиска.
  - Правила совпадения те же, что в `planner.interests`. Более конкретное место стоит первым
    (мавзолей раньше города Туркестан).
  - Есть исключения: «Иссык-Куль» — это не озеро Иссык.
  - Расстояние считается по прямой от центра Алматы и округляется до 10 км. Это не дорожное
    расстояние, и ИИ так и говорит.
- **«Это заведение, а не поездка».** «ресторан Туркестан», «Turkistan cafe», «улица Туркестанская»
  и «Hotel Astana» не считаются местом вне зоны. Такое пожелание ищется как обычно (еда и напитки —
  по словарю `interests`, остальное — `VENUE_STEMS`).
- **Поиск** (`search_places`): на место из справочника отвечает
  `{"places": [], "outside_area": {id, name, region, distance_km}, "note": …}`, а не «nothing found».
  Если указана категория, поиск идёт как раньше. Живой маршрут ищет через тот же поиск, поэтому
  для Чарына не появится остановка-подмена.
- **Генератор** (`_resolve_must_have`): место из справочника становится
  `MustHave(how="outside", places=[])`. Раньше чтение по категории могло подставить парк или озеро
  Алматы вместо «Кольсайских озёр». `must_have_unmet` теперь получает причину `outside_area` с
  `place_name` и `outside_area`. Если турист сам выбрал место на живой карте, его выбор важнее.
- **Бриф** (`update_trip_brief`): для новых обязательных пожеланий вне зоны в ответ инструмента
  добавляется `outside_area: [{id, name, region, distance_km, wish}]`. ИИ может сказать честно сразу,
  не дожидаясь `build_trip`. Само пожелание из брифа не убирается.
- **Аналитика:** серверное событие `wish_outside_area`.
  - У него одно свойство, `place` — id из справочника (белый список). Ни пользователя, ни установки, ни поездки,
    ни слов туриста в нём нет.
  - Событие пишется один раз на новое пожелание. Повтор того же пожелания (в любом регистре) не
    считается.
- **Промпты:** новые версии `trip_brief.{ru,en}.v5` и `guest.{ru,en}.v3`. При `outside_area` ИИ
  говорит, что эта версия Jol планирует Алматы и горы рядом, а поездки по Казахстану появятся
  позже. Он не говорит «такого места нет» и не подменяет место алматинским без просьбы. В описании
  `build_trip` для модели то же правило.

## Ревью координатора

Принято. Шаг закрывает поведение v1 из SSOT §5.4: Чарын, Кольсай и Туркестан больше не
превращаются ни в «ничего не нашёл», ни в парк Алматы.

Ограничения и долги:

1. **Справочник маленький и ручной.** Место вне зоны, которого в нём нет (например, Каркаралинск),
   по-прежнему даёт `no_place`. Пополнять по мере вопросов; в Ф20 (Ш-58) справочник заменят
   данные регионов.
2. **Гостевой чат спрос не пишет.** Поиск может вызываться много раз на одно место, а дедупликации
   без чата нет. Спрос считается только по обязательным пожеланиям зарегистрированных.
3. **Одно пожелание с двумя местами** («Чарын и Медеу») целиком считается вне зоны. Обычно модель
   пишет пожелания по одному; если на настоящей модели это станет проблемой, делить пожелание.
4. **Уже построенные поездки** хранят старую причину `no_place` до пересборки.
5. **На настоящей LLM не проверено:** ключа DeepSeek пока нет. Поведение проверено на фейковой
   модели и по тексту промптов. При первом прогоне `make llm-smoke` проверить сценарий «хочу на
   Чарын».
