# Ревью Ш-53 — LLM-провайдер DeepSeek

## Что сделано

1. `server/app/providers/llm/deepseek.py` — адаптер `DeepSeekLLM` по контракту `LLMProvider`.
   Chat Completions (совместим с OpenAI): `POST {base}/chat/completions`, `stream: true`,
   `stream_options.include_usage`. Разбор SSE: строки `data:`, `[DONE]`, комментарии
   `: keep-alive` игнорируются. Текст отдаётся кусками; вызовы инструментов собираются из
   дельт `function.arguments` по `index` и отдаются после текста; затем `Usage` и `Done`
   (`stop` / `tool_calls` / `length`). История с `tool_calls` и ответами инструментов
   воспроизводится в формате OpenAI. Системный текст — отдельным первым сообщением; текст
   пользователя по-прежнему идёт только как данные (сообщения `user`), в системный промпт не попадает.
2. Ошибки: 401/403 → `LLMNotConfigured` (`llm_not_configured`); 402 → `llm_quota` (не повторяется);
   429 → `llm_rate_limited` (повтор); 5xx и сетевые ошибки → `llm_unavailable` (повтор); таймаут httpx →
   `LLMTimeout`; прочие 4xx → `llm_bad_request`. Повторы и общий дедлайн — в `ResilientLLM`, как у fake.
3. Фабрика: `LLM_PROVIDER=deepseek` (без учёта регистра). Пустой ключ → `LLMNotConfigured`
   с текстом про `DEEPSEEK_API_KEY` (API отвечает 503 `llm_unavailable`, не падает). Без ключа и
   с `fake` всё как раньше. Настройки: `DEEPSEEK_API_KEY` (`SecretStr`), `DEEPSEEK_MODEL`
   (`deepseek-chat`), `DEEPSEEK_BASE_URL` (`https://api.deepseek.com`); записи в `.env.example`
   (ключ пустой).
4. `make llm-smoke` (`app/providers/llm/smoke.py`): один короткий запрос; без ключа объясняет, что делать.
5. Существующий тест «неизвестный провайдер» поправлен: текст ошибки больше не ссылается на §16.12.

## Замечания

- Средне: формат SSE и поля взяты из документации OpenAI-совместимого API и по памяти о
  DeepSeek; живого вызова с настоящим ключом не было (ключа нет) — нужна ручная проверка
  `make llm-smoke` владельцем. Не проверено поведение `deepseek-reasoner` (поле `reasoning_content`
  адаптер игнорирует).
- Низко: клиент httpx создаётся на каждый вызов (без переиспользования соединений) — для текущей
  нагрузки достаточно.
- Низко: `deepseek-chat` не гарантирует строго валидный JSON аргументов; это ловит `parse_tool_args`.
