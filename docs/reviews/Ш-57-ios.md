# Ревью Ш-57 (iOS): регионы

Ветка `sh-57-ios`. Серверная часть (таблица `regions`, `GET /v1/regions`) делается отдельно; здесь только iOS.

## Что сделано

- **Модель региона** `Region` (`ios/Jol/Features/Regions/Region.swift`) — Codable по контракту `GET /v1/regions`
  (`id`, `name{ru,en}`, `timezone`, `currency`, `languages`, `centre`, `camera.zoom`, `bbox`, `is_default`).
  Производные: часовой пояс, центр карты, зум, символ валюты (KZT → ₸, USD, EUR, RUB, GBP, CNY; неизвестный код
  показывается как есть), проверка «точка внутри bbox», название региона на языке интерфейса.
- **Текущий регион** — `Region.current` (статическое значение под `OSAllocatedUnfairLock`): форматтеры в приложении
  статические и вызываются из разных мест, поэтому передавать регион параметром в каждый из них было бы большой
  переделкой. Значение выставляет `RegionModel`.
- **Встроенный регион** (`Region+BuiltIn.swift`) — Алматы со значениями, которые были в коде: центр 43.2380, 76.9450
  и зум 11 из бывшего `AlmatyCamera`, часовой пояс `Asia/Almaty`, валюта KZT, bbox `76.70, 42.95, 77.30, 43.45`
  (из серверной `ALMATY_BBOX`).
- **`RegionModel`** (`@MainActor @Observable`, в `AppContainer.regions`): `load()` запрашивает `/v1/regions` без
  авторизации через существующий `APIClient`; при успехе выбирает регион с `is_default` (иначе первый) и кладёт
  ответ в кеш `UserDefaults`; при ошибке (нет сети, 404 на старом сервере, пустой список) остаётся то, что уже
  было: кеш последнего ответа, а если его нет — встроенный регион. Загрузка запускается из `RootView` при старте.
- **Городские константы убраны:**
  - `AlmatyCamera` удалён; центр и зум карты — `Region.current.center/zoom` (`MapView`);
  - `PlaceFormatting.almaty` удалён; везде `Region.current.timeZone` (время прибытия, события, бронирования,
    «открыто сейчас», день недели, дата поездки в чате, `YYYY-MM-DD` в ленте событий);
  - ₸ как валюта — `Region.current.currencySymbol`: цены в «Как добраться», карточке места, карте поездки, бюджет
    в графе чата, ставка бонусов, подписи полей цены/проезда/входа;
  - локальная проверка «точка в зоне работы» (`GeoPoint.isInServiceArea`) использует bbox региона вместо чисел
    Алматы;
  - тексты «You seem to be outside Almaty…» и «Directions work inside Almaty only…» теперь подставляют название
    региона (`%@`; русский текст — «вне региона «Алматы»» без склонения).
- **Локализация:** шесть ключей `Localizable.xcstrings` заменены на ключи с `%@` (ставка бонусов, три подписи
  цен, два сообщения про зону маршрутов); русские переводы сохранены.
- **Заглушка API** (`-JolStubAPI`) отдаёт `GET /v1/regions` по контракту (регион Алматы); в режиме «офлайн» заглушки
  запрос падает, и работает фолбэк.
- **Проверка в CI:** `custom_rules.no_city_constants` в `ios/.swiftlint.yml` (severity error) — запрещает
  `Almaty|ALMATY|AlmatyPoint|AlmatyCamera|Asia/Almaty` в коде `ios/Jol` (комментарии не проверяются). Проверено
  вручную: временный файл с `"Almaty"` даёт ошибку.
- Файл проекта пересобран `xcodegen generate` (`ios/project.yml` — источник).

## Исключения из правила

- `ios/Jol/Core/Networking/UITest*.swift` — стабы UI-тестов (данные, а не логика);
- `ios/Jol/Features/Regions/Region+BuiltIn.swift` — встроенный регион по умолчанию;
- комментарии (rule не смотрит на комментарии; из кода приложения я их всё равно убрал);
- не в области правила: `JolTests`, `JolUITests` (там «Almaty» — текст в тестовых фразах) и
  `Localizable.xcstrings` (данные).

Правило не ловит `KZT` и `₸`: они встречаются в `Region.swift` (таблица символов) и в именах серверных полей
(`costKztMin` и т. п. — контракт API, не менялся).

## Тесты

`ios/JolTests/RegionTests.swift` (7 тестов): декодирование контракта; `load()` переключает регион и кеширует ответ,
после «перезапуска» без сети берётся кеш; фолбэк на встроенный регион при ошибке сети; 404 и пустой список;
форматирование цены (`DirectionsFormatting`, `PlaceFormatting`, `TripFormatting`, `BriefFormatting`) и времени
(`EventsModel.dateString`, `weekday`) через регион — Алматы и Берлин/EUR; значения встроенного региона и bbox.
Остальные тесты не менялись по смыслу (`AlmatyCamera.center` → `Region.current.center`, `testAlmatyCamera` →

## Что не проверено и оговорки

- С настоящим сервером не проверялось: серверная часть делается параллельно; форма ответа проверена только по
  контракту из задания и стабом.
- **Карта берёт центр и зум региона при создании.** Если ответ сервера пришёл позже, чем создана карта, камера не
  перелетает; со следующего запуска берётся кеш. Реальный сервер отдаёт центр Алматы 43.2389, 76.9455 (по сообщению
  координатора), встроенный — 43.2380, 76.9450 (старая константа iOS): разница около 100 м, встроенное значение
  оставлено как было.
- Выбор региона пока один — тот, что с `is_default`; переключателя регионов в интерфейсе нет (не требовалось).
- Локальная проверка зоны теперь по bbox региона (`76.70…77.30`, `42.95…43.45`), раньше была уже
  (`76.70…77.20`, `43.0…43.45`, как у серверной `AlmatyPoint`). В узкой полосе точка проходит локально и,
  если сервер ещё проверяет по старому прямоугольнику, получит ответ 422 от него; сервер в этой же задаче должен
  перейти на регион.
- Валюта влияет только на символ; суммы по-прежнему в тенге и серверные поля называются `*_kzt` (конвертация —
  OPEN(SSOT §16.2)). Название поля `tenge` в `PlaceFormatting.tenge` оставлено ради минимума правок вызовов.
- Скриншоты не нужны: внешний вид на регионе «Алматы» не менялся.
