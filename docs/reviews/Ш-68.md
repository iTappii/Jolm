# Ревью Ш-68 — ИИ рекомендует сам

## Что сделано
- **Якорь** (`server/app/places/recommend.py`, `choose_anchor`): геопозиция туриста (если приложение
  прислало в этом запросе и она внутри региона) > жильё из брифа (`brief.lodging {lat, lon}`; в брифе
  такого поля пока нет, функция готова для брони жилья) > центр региона по умолчанию. Явный `near`
  (Ш-67) переопределяет якорь; `near` не найден — якорь и заметка `near_not_found`.
- **Сигналы в результате `search_places`** (по месту, только те, что есть в данных): `distance_m` от
  якоря, `popularity`, `open_now`, `closes_at` / `open_24h`, `price_level` (1–3) + `avg_check_kzt`,
  `entry_kzt`, `address` (до 60 символов), `category` словами (вместо slug), `match` блюда (Ш-67).
  Нет данных — ключа нет (ничего не выдумывается). На верхнем уровне `anchor`
  (`tourist_location` / `accommodation` / `city_centre` / `landmark`) и `ranking` — подсказка модели.
- **Порядок «лучшее для туриста»** (константы с комментариями в начале `recommend.py`):
  `score = 2·бонус_уровня_блюда + 0,40·близость + качество·(0,4 + 0,6·близость)`, где
  близость = `1/(1+(d/1500 м)²)`, качество = `0,30·популярность/100 + 0,20·открыто (нет часов = 0,5) +
  0,10·полнота (часы, адрес)`; закрыто сейчас — счёт ×0,5. Уровень блюда (меню > название > кухня >
  родственная) никогда не перебивается сигналами. Кандидатов 30, модели — топ `limit` (по умолчанию
  6, было 5). Поиск по части названия (без категории и без блюда) остаётся в порядке схожести имени,
  сигналы только добавляются.
- **Приватность.** Необязательный `location {lat, lon}` в `POST /v1/chat/guest` и
  `POST /v1/chats/{id}/messages` (`server/app/chat/location.py`: диапазоны, NaN/inf отклоняются, 422).
  Используется один ход: не пишется в БД (тест обходит все таблицы), не логируется (`repr` скрывает
  числа, аргументы инструмента от модели координат не содержат), в модель уходят только расстояния,
  округлённые до 100 м, а у мест такого ответа нет `lat/lon` (иначе по расстояниям до известных точек
  позицию можно было бы восстановить). Карта по-прежнему получает координаты мест.
- **Промпты** `trip_brief` v11 и `guest` v7 (RU + EN): выбрать 2–3 места из начала списка, к каждому
  одна причина только из сигналов, предложить «показать ещё» (зарегистрированному ещё и «добавить в
  маршрут»; про вход гостю не пишем — это делает приложение), не просить ориентир, без «сейчас поищу» и
  «я не выдумываю данные», «по отзывам» не говорить. Правила v10/v6 сохранены. Старые версии не тронуты.
- **iOS (малое).** `location` в обоих запросах чата. `LocationProviding.knownLocation()` — последняя
  точка, только если доступ уже выдан и точке меньше 10 минут; новый запрос разрешения не показывается
  и ничего не ждётся (если точки нет, просто прогревается `requestLocation()` для следующего
  сообщения). `docs/legal/app-privacy.md` дополнен п. 5.
