# 0001. Технологический стек

- Статус: предложено (сервер — SSOT §14 [предложено], подтверждение: SSOT §16.13)
- Дата: 2026-11-21

## Контекст

SSOT фиксирует iOS (Swift + SwiftUI), MapLibre + OSM, PostgreSQL + PostGIS, Open-Meteo и правило
«без ORM» (`JOL_SSOT.md §14`, `§14.1`). Серверный стек в SSOT лишь предложен (Python + FastAPI).
Остальное (очередь, стрим чата, маршрутизация, формат тайлов) нужно выбрать так, чтобы было
минимум движущихся частей для маленькой команды (`TECH_PLAN.md §3`).

## Решение

- **iOS:** Swift + SwiftUI, iOS 17+ (`JOL_SSOT.md §14` [решено]).
- **Сервер:** Python 3.12 + FastAPI (uvicorn). Воркер — тот же код, отдельный процесс.
- **БД:** PostgreSQL 16 + PostGIS 3 — единственное хранилище состояния.
- **Доступ к БД:** `psycopg` 3, **без ORM**, только чистый **параметризованный SQL**;
  имена таблиц/колонок — только из белого списка (`JOL_SSOT.md §14.1`, `TECH_PLAN.md §0 п.5`).
  SQL лежит в `app/<module>/sql.py`.
- **Миграции:** обычные `db/migrations/NNNN_описание.sql`, только вперёд, применённые файлы не
  редактируются; свой раннер `db/migrate.py` с таблицей `schema_migrations`.
- **Стрим чата:** Server-Sent Events (`text_delta`, `graph_node`, `map_places`, `brief_updated`,
  `route_ready`, `done`).
- **Очередь задач:** таблица `jobs` в Postgres + `SELECT … FOR UPDATE SKIP LOCKED`; без Redis/Celery.
- **Карта:** MapLibre Native + векторные тайлы OSM в формате PMTiles (Planetiler), статический
  хостинг/CDN с Range-запросами (`JOL_SSOT.md §13`).
- **Маршрутизация:** Valhalla (Docker, данные OSM Казахстана) — пешком / самокат / авто.
- Деньги — целые тенге (`bigint`), времена — `timestamptz`, часовой пояс `Asia/Almaty`.

## Последствия

- Меньше инфраструктуры: Postgres, API, воркер, Valhalla, статика для тайлов.
- Очередь в Postgres ограничивает пропускную способность, но для v1 достаточно; при росте её можно
  заменить, не меняя интерфейс `jobs`.
- Без ORM: больше ручного SQL, зато полный контроль и соответствие SSOT; каждая миграция — необратимый
  шаг вперёд (откат делается новой миграцией).
- SSE однонаправленный: запросы клиента идут обычными POST.
- Если владелец отвергнет FastAPI (SSOT §16.13), меняется только слой сервера; БД и правила SQL остаются.
