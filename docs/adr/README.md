# Architecture Decision Records (ADR)

Короткие записи архитектурных решений Jol. Продуктовые решения живут только в `JOL_SSOT.md`;
ADR фиксируют инженерные решения и допущения из `TECH_PLAN.md` (см. `TECH_PLAN.md` §0, §2, §3, §4).

| [0003](0003-open-defaults.md) | Значения по умолчанию для открытых вопросов SSOT §16 | предложено |

## Правила

- Файл: `NNNN-короткое-имя.md`, номер по порядку, принятые ADR не переписываются —
  новое решение оформляется новым ADR со статусом «заменяет NNNN».
- Если ADR меняет продуктовое решение — сначала правится `JOL_SSOT.md` (включая журнал §17).
- Статусы: `предложено`, `принято`, `отклонено`, `заменено NNNN`.

## Шаблон

```markdown
# NNNN. Название

- Статус: предложено | принято | отклонено | заменено NNNN
- Дата: ГГГГ-ММ-ДД

## Контекст
Какая проблема и какие ограничения (с ссылками на SSOT).

## Решение
Что решили делать.

## Последствия
Плюсы, минусы, что становится обязательным или запрещённым.

## Ссылки
- `JOL_SSOT.md §x`
- `TECH_PLAN.md §y`
```
