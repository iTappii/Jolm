## 1. Как работаем (обязательно)

- Источник правды — `JOL_SSOT.md`. Меняется продуктовое решение → сначала SSOT и его журнал (§17),
  потом план, потом код. Реализация — только по `TECH_PLAN.md` (шаги `Ш-xx`, DoD, статус в плане).
  Работа вне плана → сначала добавить шаг в план (так добавлены Ш-22a, Ш-23b, Ш-23c, Ш-32a).
- Без ORM, только параметризованный SQL через psycopg 3; миграции — новые `db/migrations/NNNN_*.sql`
  (последняя — `0026_trip_leg_variant.sql`), применённые не править.
- Правило 8 плана: таблица с `place_id` → добавить в `data/osm/merge.py` (`merge_place`) с тестом;
  FK пользовательских данных на `places` — без `ON DELETE CASCADE`. Новая персональная таблица →
  удаление аккаунта (`DELETE /v1/me`) её чистит + тест в `test_account_deletion.py`, `AUTH_TABLES`.
- После каждого шага — ревью в `docs/reviews/Ш-xx.md` (требование владельца): что сделано,
  «Проверки» с командами и результатами, замечания по важности. Координатор дописывает раздел
  «Ревью координатора»: сам читает код, сам перезапускает проверки, затем ставит статус.
- Схема работы этой сессии: координатор (Opus) + агенты Sonnet. Один агент на `ios/`, один на
  `server/` в общей копии; серверные тесты пересоздают общую тестовую БД — их гоняет только один
  агент. Второй iOS-агент — только в отдельном worktree и на другом симуляторе. Агенты не правят
  `TECH_PLAN.md`, `JOL_SSOT.md`, этот файл, не коммитят (кроме worktree) и не делают `git stash`.
- **Не верить отчётам и ревью на слово.** Коммит `26d7f42` (сделан другими инструментами) отметил
  Ш-47…Ш-49 готовыми без iOS-части и описал несуществующий эндпоинт — это нашлось только при проверке.
- `graphify update .` после изменений кода. Коммиты — в ветку `sh-22-24-auth`, с
  `Co-Authored-By`; владелец разрешил коммитить проверенные шаги.

## 6. Ревью сессии (координатор, 2026-11-21)

**Сильные стороны.** Каждый шаг закрыт с тестами и отдельным ревью; координатор перезапускал
проверки сам. Сервер: ~831 тест, Ruff чисто. iOS: 138 юнит + 48 UI-тестов, SwiftLint 0.
Правило «без ORM» и правило 8 соблюдены во всех миграциях (`0008`…`0025`), удаление аккаунта
покрыто тестами для всех персональных таблиц. Пользовательский текст никогда не попадает в
системный промпт (бриф и память идут блоками данных).

**Риски и долги (по важности):**
1. **Нет реального LLM** (SSOT §16.12): чат, бриф и выжимки памяти проверены только на fake-модели;
   промпты не проверены на настоящей модели. Это главный продуктовый риск.
2. **Данных мало:** у мест OSM почти нет цен, часов, адресов, фото — бюджет держится на допущениях
   (ADR 0003), варианты экономии почти всегда `feasible:false`. Нужна ручная редактура/UGC.
3. **Внешние сервисы не подключены:** SMS, почта, APNs, S3, платный Open-Meteo, Apple Sign In —
   все работают на заглушках; ни один не проверен вживую.
4. **Не проверено на реальном iPhone:** геопозиция, автоввод кода из SMS, свайп от края, Dynamic Type.
5. UI-тесты нестабильны сразу после загрузки симулятора — в CI прогревать симулятор.
6. Мелкие долги перечислены в разделах «Ревью координатора» каждого `docs/reviews/Ш-xx.md`.
